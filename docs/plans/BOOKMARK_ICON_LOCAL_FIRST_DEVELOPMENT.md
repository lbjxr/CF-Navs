## 1. 计划结论与范围

### 1.1 为什么不是“恢复旧缓存代码”

上一会话已确认：本地优先曾存在，随后为修复匿名对象的权限撤回及部署平台 Browser Cache TTL 覆盖问题，对象代理改为客户端 `no-store`，旧缓存被清理。边缘命中和页面 `blob:` 不等于浏览器持久副本。

因此实施顺序必须是：**可信授权与内容身份 → 服务端专用取得协议 → 可清理的受控存储 → 全部实际展示链路 → 迁移、性能和部署验收**。不能通过删除 `no-store` 拒收规则或把 SW 改为对象 cache-first 完成本需求。

### 1.2 已裁定约束映射

| 裁定 | 本计划落实方式 | 不得扩大为 |
| --- | --- | --- |
| IC-D01 标准模式 + 可信设备，默认关闭 | 设备级偏好，登录会话与存储能力共同决定是否启用 | 匿名默认持久化或升级自动开启 |
| IC-D02 可信设备可保存私密图片 | origin、数据集、当前会话、对象与内容版本隔离；退出清理 | 本地加密保险箱或跨身份共享 |
| IC-D03 最长 24 小时且不晚于会话到期 | 认证回执续租、一次性到期调度、异常时钟拒绝离线使用 | 图片下载成功续租或离线无限使用 |
| IC-D04 正文 10 MiB | 两期联合执行 1,000 条、单图 512 KiB、索引 512 KiB；正文高水位清至 8 MiB | 分类另开额度或直接放宽原 5 MiB 审计 |
| IC-D05 两期范围 | 一期书签完整链路；二期分类图标独立实现和验收 | 一期完成即宣称全部图标完成 |
| IC-D06 旧缓存按需重建 | 不认领身份/版本不明副本，仅清理已知旧命名空间 | 清空云端、全库预热或要求逐条手动刷新 |
| IC-D07 独立物化协议与兼容回滚 | 保留普通代理；新能力不可用时降级；上线前备好清理兼容包 | 任意旧版本直接回滚或缓存普通代理响应 |

一期覆盖：首页卡片、经常访问、普通搜索、Spotlight、后台书签列表、编辑保存和显式图标刷新。二期覆盖分类导航、分类区域、搜索分组、后台分类列表与编辑保存。两期都不包含全库预热、跨设备同步、自动转码、全站数据层重构或新存储服务。

## 3. 目标架构与状态所有权

### 3.1 模块边界

新增模块名称为建议落点；只有职责被实际调用时才创建。不要为二期预先提交空实现。

| 层 / 建议落点 | 唯一负责的状态与副作用 | 小接口 / 依赖 |
| --- | --- | --- |
| `shared/iconLocalCopy.ts`（拟新增） | 无状态：描述、协议版本、成功/拒绝/冲突语义 | 前后端共用；不依赖 DOM、Svelte、D1 |
| Worker 图片规则（`worker/lib/`） | 纯字节校验、摘要、结果分类 | 输入字节/元数据，输出标准图片或明确失败 |
| D1 访问层 | 正文、内容版本、写入代次、数据集代次的原子持久化 | 条件读写；不依赖路由或 UI |
| Worker 图片用例编排 | 鉴权后读取、按需取得当前对象图片、条件提交、构造响应 | 路由 → 用例 → 图片规则 / 数据访问；不直接复用普通代理 HTTP 响应 |
| `authStore` + 设备会话边界（拟 `iconDeviceState.ts`） | authStore 仍唯一拥有认证；设备边界拥有信任偏好、租期、图标访问代次和状态通知 | 订阅认证与数据事件，不再保存一份 Token |
| `dataService.ts` | 当前数据快照、描述差集、刷新代次、认证回执提交 | 原刷新入口向设备边界和协调层发送小型事件 |
| `iconCachePolicy.ts`（拟新增） | 无状态：读写许可、租期判断、失效与淘汰决策 | 可注入时钟；不访问浏览器存储或网络 |
| `iconCopyStorage.ts`（拟新增） | 正文/索引、锁、容量、持久清理栅栏、恢复 | `read` / `commit` / `invalidate` / `clearScope` / `stats` |
| `objectIconLoader.ts`（拟新增） | 页面在途任务、并发队列、使用者句柄与内存 Blob | `acquire(descriptor)` 返回可观察状态及 `release()`；调用策略/适配器/API |
| 展示组件与设备设置区 | 局部交互、loading/error、布局和辅助技术反馈 | 申请/释放句柄，发出操作；不直接读写持久副本 |
| Service Worker | 原有 shell、静态资源和既定公共资源 | 不获取可信 Token，不读取/返回私密图标副本 |

依赖固定为：**UI → 协调层 → 纯策略 / 存储 / API**。会话和数据事件由既有服务向下提供，纯策略不反向读取 Store；存储层不发网络请求；图标协调层不承接书签 CRUD。

### 3.2 展示句柄与真实接入

- 句柄状态至少区分：等待、成功图片、文字/空图、网络降级、无权限、租期暂停、已释放；不要用一个 `null` 同时代表删除、超时和未加载。
- 每个使用者获得独立 object URL；同一 Blob 可共享，但一个组件释放不能破坏其他组件。
- 在本地检查完成前不先给 `img.src` 挂远程地址，避免命中后仍发生下载。
- 卡片仍按当前可见性触发；不得因改成主动 fetch 而绕过 IntersectionObserver/懒加载，把隐藏分类全部排队。
- 同一页面的同作用域、同对象、同内容版本最多一个在途正文任务；不同标签需在锁内二次查命中，不能各写一份重复正文。无需一期实现跨标签网络广播框架。
- 组件销毁、对象变化、退出和权限撤回时均释放；取消任务需引用计数，不能由一个离开的使用者取消其他使用者仍需的请求。

## 4. 数据身份、写入与一致性设计

### 4.1 五种版本不可混用

| 逻辑字段（拟新增或扩展） | 来源与含义 | 变化时机 |
| --- | --- | --- |
| `dataset_epoch` | 服务端内部随机数据集代次；不是凭据 | 首次初始化、重装、替换导入；不随普通部署改变 |
| `content_revision` | 对经验证的实际 MIME + 图片字节做带算法前缀的 SHA-256 摘要 | 成功图片内容变化；相同字节不制造新版本 |
| `icon_write_epoch` | D1 图片写入意图的单调代次，不是内容摘要 | 换源、清空、显式刷新等竞争操作开始时推进，阻止旧工作覆盖新意图 |
| `data_version` | 沿用当前数据/权限新鲜度标记 | 内容发布及可见性/业务变更；不作为所有图标的缓存键 |
| `access_epoch` / `schema_version` | 本地访问栅栏 / 图片存储格式版本 | 会话/清理事件 / 真正格式不兼容；均不跟应用构建指纹绑定 |

描述至少包含对象类型、ID、数据集代次、图片状态、内容版本和所属数据版本。图片状态区分 `ready`、`unknown`、`empty`、`text`；取图失败另用结果类型表示，不把 unknown/null 当作显式清空。

- 版本未知的旧数据不伪造摘要；当前需要该对象时才惰性计算或获取。
- 文字/表情不进入正文存储；确定性生成图以实际生成输出为准，标题只在改变生成结果时影响版本。
- 源 URL 变化或写入代次变化，即使最后字节相同，也要先核对当前对象描述；不得把迟到响应贴到新源。
- 普通插入沿用 AUTOINCREMENT；显式重建/复用 ID 必须同时更换数据集代次。若新增保留全库代次的局部复用功能，须加入对象实例标识后才能接入缓存。
- 聚合只增加小型描述，不携带全部图片。对匿名无权对象，不返回摘要、名称或图片存在性；分类祖先关系仍参与可见性计算。

### 4.2 必须覆盖的服务端写入口

| 入口 | 计划改动 | 验证重点 |
| --- | --- | --- |
| `createBookmark` / `updateBookmark` + 路由调用 `cacheBookmarkIconBlob` | 统一初始化/推进写入代次，保存后返回当前描述 | 改文案不误删图；换源 A→B→A 无迟到覆盖 |
| `/:id/icon-cache/refresh` | 区分 unchanged / updated / cleared / transient-failure；保持旧字段兼容 | 同字节版本不变；失败保留旧成功图 |
| 普通 `/icon/:id` 的惰性补全 | 通过统一条件写入，不再裸调 `setIconBlob` | 代理安全顺序不变；后台旧抓取不能覆盖新保存 |
| 损坏 blob 清理、data URI、生成图、Iconify 成功数据 | 校验后写版本；损坏仅标记需修复，不冒充用户清空 | 临时 fallback 不成为成功图片；公共来源不绕过对象许可 |
| `importData`（replace） | 新代次与替换行在同一 D1 原子批次提交；不信任备份内部版本 | 失败不留下半个新数据集；旧 ID 不串图 |
| merge 导入、浏览器同步新增 | 走同一初始化规则；不改变导入/同步业务语义 | D1 参数分块重新计数；新增字段不突破语句参数上限 |
| 删除及级联删除 | 发布对象消失，回收对应本地引用 | 不能以失败回退恢复已删除内容 |

条件提交必须同时验证当前数据集、对象、源/写入代次与预期旧版本。正文和版本一起更新，失败返回冲突而非静默成功。需要对外发布的内容变更，其 data_version 也在同一提交边界更新；提交成功后再失效 runtime/public 缓存。抓取/散列不在数据库事务内等待网络；返回后用条件 SQL 和必要的 D1 batch 完成原子提交。

正文来源统一收口到业务用例，但普通代理和专用协议保持各自鉴权与缓存响应边界。禁止从一个路由 fetch 另一个路由再克隆其响应作为“可信副本”。

### 4.3 惰性补全与版本发布收敛

- 已有正文但无摘要：只对当前需要对象补摘要，响应附完整描述；前端把描述补丁合入当前快照，避免下次刷新仍认为 unknown 而再次下载。
- 首次 unknown→ready 只补元数据且不改变已发布内容时，不为每张图强制触发全量数据刷新；协调层按当前请求代次接收补丁。补丁必须绑定 dataset_epoch、对象 ID 和 icon_write_epoch：后续同写入代次的 unknown 描述可保留已核实补丁，源/写入代次变化或 empty/deny 则立即丢弃。补丁不得延长认证租期，也不能覆盖新的权限结果。
- 聚合的对象描述、dataset_epoch 与 data_version 必须来自一致的数据库读取边界；实现时使用可证明一致的 D1 批次或前后版本复核，避免“旧对象 + 新版本”被客户端长期当作最新。该聚合一致性方案不改变单独版本热路径一条查询目标。
- 替换已发布内容、显式清空、换源必须发布可观察变化；不通过“永远不 touchDataVersion”掩盖新鲜度问题。
- 本页面重复触发的数据刷新合并在现有刷新编排中；跨标签收到变化后走既有版本检查，不新增每图版本查询。
- 发布方案需验证其他设备最终可发现变化，并测量一批惰性补全时的聚合请求数。若无法证明既收敛又新鲜，不通过 IC-P02 的设计门。
- 新字段迁移只做结构和必要初始化，不在首个首页请求扫描、散列全库图片。数据集内部 key 不加入用户设置或备份白名单。

### 4.4 新旧写入兼容门

新增列本身不足以保证混合版本安全。旧代码只更新 blob 时，原摘要可能变成错误描述。

首选方案是在幂等迁移中加入最小保护：对未同步维护版本的旧 SQL 写入，将描述置 unknown、推进写入栅栏并发布数据新鲜度变化；新用例按原子条件更新完整状态。保护可采用 SQLite 触发器，但必须测试实际 D1 支持、递归行为、同字节/不同编码及新旧写入交错，不能仅靠源码匹配断言。

如果该保护不能可靠成立，则**不支持旧服务端写入器与可信能力同时运行**：先关闭副本能力、完成兼容写入版本切换，再开放能力；回滚只能使用保持版本保护的兼容包。该限制须在实现设计门明确选择并写入发布说明，不能边上线边决定。

## 5. 专用副本协议与租期设计

### 5.1 最小能力发现与认证回执

优先扩展已有 `/api/data/version` 和会话鉴权聚合响应，不为每张图或每次启动另加能力请求：

- 响应可附 `icon_local_copy_protocol`、`dataset_epoch`；只有已验证会话的响应可附 `auth_receipt`。
- 回执包含服务端校验时间、会话绝对到期、非认证用途的 `cache_scope`，并与这次客户端会话/刷新代次绑定。
- 对带 Bearer 的版本请求，即使 `public_mode=true` 也验证会话；无效返回可识别的 401，不能退回匿名成功并续租。无 Bearer 的公开访问仍不需登录。
- `cache_scope` 采用域分离的高强度摘要或等效不可碰撞标识，绑定实际会话；不沿用现有短哈希作为安全隔离保证，不保存原始 Token、用户名或图标 key。
- 在当前单管理员架构内做会话隔离，不为 A/B 场景引入多租户账号系统；A/B 测试使用受控身份更换/恢复场景。
- 数据集与版本从原有合并查询取出，维持热路径一条 D1 查询；会话校验原有内存/KV 行为另行记录，不声称“联网响应 = 实时全局撤销”。

### 5.2 推荐传输形态（技术提案，须经 IC-P01 契约评审）

推荐新建会话鉴权的 `POST /api/icon-local-copy`，以受保护 JSON 数据响应表达“取得应用可保存的数据”，一期只接受书签对象类型。POST 不表示修改用户书签；仅允许对当前请求对象进行原有语义的惰性补全。

请求字段：`protocol`、`object_type`、`object_id`、`dataset_epoch`、`expected_content_revision`、必要的当前源/写入代次。认证只走现有 Authorization，不接受查询串图标 key、客户端 trusted 声明或摘要作为授权。

成功数据：协议版本、当前对象描述、`persistence: session-scoped`、规范 MIME、实际正文字节数、base64 图片数据。使用项目 `ApiResponse` 信封，并对关键安全/冲突结果使用准确 HTTP 状态；保留旧接口字段与行为。

| 结果 | HTTP / 语义 | 客户端行为 |
| --- | --- | --- |
| 成功图片 | 200 + 已知协议 + ready 描述 | 检查身份/数据/内容、长度及解码后保存数据，不保存原 HTTP 响应 |
| 明确空图/文字 | 200 + empty/text | 按权威描述移除旧引用；不保存文字兜底为图片 |
| 描述冲突 | 409 + 当前可授权描述，无旧正文 | 合并新描述；当前仍需要时最多一次受控重试 |
| 未登录/会话无效 | 401 | 立即封禁当前作用域；不继续持久化 |
| 未知/无权对象 | 统一 404 或统一 deny 信封，不可区分存在性 | 停止该对象旧副本；不得把 deny 当作瞬时失败 |
| 协议不支持 | 明确 unsupported 或端点缺失 | 标记本轮能力不可用，按原网络展示；不每图反复探测 |
| 超限/暂时不可取得 | 明确 too-large / transient-failure，429/5xx 保留分类 | 不落盘、不清掉仍许可的成功副本；有界降级 |

端点能力缺失与对象 404 由能力协商及已知错误信封区分，不把任何 404 都当作可忽略的旧服务端。

### 5.3 传输与校验硬边界

1. 鉴权、对象权限与当前描述检查先于图片访问；专用端点不访问共享 response cache，不用旧 edge 图片配新摘要。
2. 传输使用 `private, no-store`，禁止共享缓存；按部署平台实际结果检查额外 CDN 缓存控制与错误响应头，不能以本地 Worker 测试替代平台测试。
3. 仅该已知协议的成功数据可被物化。普通代理、私密预览、任意 no-store API 和未知协议响应均不能走例外；SW 不截获该端点。
4. 单图原始正文上限 524,288 B；base64 最大 699,052 字符。建议协议总响应上限 768 KiB，元信息另设小上限，实施时以测试确定；流式读入时即限制总量，不等 `response.json()` 无限分配后才检查。
5. 复用并收紧 `worker/lib/iconData.ts` / `iconResponses.ts` 的合法图片检查：支持的 MIME、声明与实际字节、摘要一致性、实际解码；HTML、opaque、重定向错页、空字节、损坏内容、`X-Icon-Fallback: 1` 一律不可保存。
6. SVG 只通过图片解码展示，不能插入为执行型 DOM；沿用外源请求的安全和大小边界，不扩大 SSRF 能力。
7. 写入受控存储时只构造规范图片数据，不克隆原始 Response，不保留认证头、外源 URL、Set-Cookie 或临时 key。
8. 首访选择专用协议或普通展示的一条路径，不能先下普通代理图片再为持久化下第二遍。超限/不支持导致的必要降级另计并说明，不藏进成功命中率。
9. 内存已有的 data URI（编辑结果、生成图）若有同等可信的当前服务端描述与明确保存语义，可走同一校验入口而不新增 HTTP；未保存预览、无版本旧实体只在内存展示。

### 5.4 租期状态机

`lease_until = min(last_online_auth_check + 24h, session_expires_at)`。

- 本地命中、图片成功、普通公共接口成功、失败重试均不能续租。只接纳当前会话的认证回执；迟到回执不能复活旧会话。
- 启动时有同作用域、同数据集的有效快照且租期内，可先恢复图片，再走现有后台刷新。明确这是已接受的陈旧窗口，不是已完成在线认证。
- 到期转为“暂停使用”；可以保留不可读正文等待同会话重新认证，不把超期与退出永久撤销混成一个操作。
- 退出、401、身份切换、撤销信任先推进访问代次、停止展示/读写，再清磁盘；退出接口失败仍封禁本机副本，远端撤销失败另行提示。
- 使用一次性到期调度；焦点、pageshow、visibility 恢复和读取前再次校验，覆盖休眠/冻结。在线恢复复用既有刷新，不另建周期定时器。
- 同会话重开时用当前本地会话计算相同的域分离标识，与已认证回执的 cache_scope 对照；本地计算只作隔离匹配，不产生认证或续租能力。新会话即使保留信任偏好，也必须先收到新认证回执，不能直接继承旧租期。
- 时钟缺失、回拨或回执异常拒绝离线；结合最近观察时间和运行期间单调时钟检查，不承诺抵御用户主动篡改本机存储/时钟。

## 6. 浏览器持久存储、预算与清理

### 6.1 实施设计门：单一 IndexedDB 后端

实施时选择需求允许的 IndexedDB **替代**方案，不和 Cache Storage 双写。原因是正文、索引、容量计数与撤销栅栏必须在同一跨标签事务中提交；Cache API 需要额外日志、互斥和补偿清理。原生 IndexedDB 可以在正文写入后索引失败、退出发生于提交途中等场景直接回滚，不新增数据库依赖。

- 数据库名为 `cf-navs-object-icons-v1`，三个 store：control（当前作用域/代次/计数）、entries（轻量对象索引）、bodies（唯一 Blob 正文）。同 origin 的读写事务负责串行提交，不另建 Web Locks 或跨标签网络广播。
- 全局作用域只保存于 control，索引条目保留对象/数据集身份及当前 generation；切换作用域在同一事务清除旧正文与索引。避免每条元数据复制完整会话标识：1,000 条 SVG 的重复索引原本会超过 512 KiB，必须去重而不是加预算。
- 常规命中只读取控制记录、目标索引与目标 Blob；只有容量压力或显式修复才遍历索引。LRU 使用记录有界合并写，由流程层调用 flushTouches，不增加周期轮询。
- 不可用/配额/损坏/迟到工作/清理失败返回可区分错误；无 IDB 时降级为内存或原网络展示，不偷偷写 localStorage 图片。
- 原生验证入口为 `npm run test:icon-storage`，使用隔离 Chrome 与纯合成数据，覆盖事务回滚、同 origin 双标签、容量和新文档恢复。完整 UI、同 profile 浏览器重开及生产验证仍由后续工作包负责。

### 6.2 索引与事务顺序

1. 正文的协议、摘要和解码校验在进入存储前完成；存储额外检查尺寸、MIME、对象身份和元数据大小。
2. 在读写事务内核对 control 的 scope/generation/enabled 与调用方捕获的当前许可。延迟激活必须提供先前观察到的控制代次，不能覆盖已经切换的会话。
3. 计算覆盖/新增后的联合预算；必要时淘汰非活跃 LRU。预算不足或异常中止整个事务，原成功正文、索引和计数一起保留。
4. 正文、索引、计数原子写入；提交前再次检查当前许可。退出/清理在同一数据库事务队列封禁并清除，两标签的迟到写入不能复活旧代次。
5. 单条正文缺失/索引损坏触发显式修复，按条剔除坏数据、回收孤儿并重算计数，不按每次图片命中扫描全部缓存。
6. 一期每对象保存一条最近成功版本。新版本验证成功并提交前保留旧版；替换由事务原子完成，不另存双份成功正文。跨对象去重不是一期前提，若后续实现必须保持独立授权引用与预算统计。

### 6.3 联合预算与降级

- 正文硬上限 10,485,760 B；有效引用上限 1,000；单图 524,288 B；索引序列化 UTF-8 上限 524,288 B。索引备份/恢复日志也需计量，不以“内部元数据”无限扩容。
- 正文达到/超过高水位时，按 LRU 分批淘汰至不高于 8,388,608 B，并满足条目/索引上限；插入前预估新增后占用，不让并发任务各自使用完整额度。
- 活跃图片句柄仍可使用内存 Blob；LRU 不应使在屏图片破裂。不能回收的活跃项使预算不足时拒绝本次持久化，不突破限额；内存单独测量并在 release 后回收。
- quota、索引损坏、正文缺失按条处理；失败/兜底不写长期缓存。未变化合格图片零请求目标不涵盖超限、未访问或被驱逐的条目。
- 旧会话/旧数据集待清理正文也计入 origin 实际占用；新作用域不得另开满额绕过 10 MiB。清理失败时保持封禁并报告，不开放旧作用域。
- 二期共享同一索引、锁和预算，不另开“分类额度”。

### 6.4 跨标签与清理语义

在现有 `api.ts` 的 storage 通知基础上形成**一个**会话/设备事件入口，同标签直接派发，其他标签监听；不要再并存第二套独立认证 Store。事件只携带代次/类型，不包含 Token 和图片信息。

撤销过程：本标签同步封禁 → 写入可恢复的撤销/清理信号并通知 → 同一 IndexedDB 事务内持久化栅栏并清理 → 报告结果。旧任务必须在网络返回、解码、锁内提交和提交后检查；被冻结标签恢复时先读取栅栏和会话，再允许显示。

若存储信号写入失败，不能报告全设备已撤销成功；本标签保持封禁并提示其他标签/磁盘清理未确认。清理锁等待或进程崩溃不能删除撤销标记，下一次启动先恢复清理，后开放新的有效作用域。

“清理此设备图标副本”只清正文和引用、推进代次以阻止旧写入，信任偏好可保留；清理完成后仅当前可见对象按需重新加载。“关闭并清理”同时关闭偏好。两者都不删除云端书签、D1 图片或全站设置。

### 6.5 数据快照的单正文约束

在 `dataService` 的快照投影边界处理，而不是修改 UI 实体语义：

- 内存中可保留正在编辑/刚保存的图片；持久快照移除 `icon_blob`，以及作为嵌入图片正文的 `data:image/*` 字段，改存轻量描述。二期对分类采用同样规则。
- 可信且当前许可的图片只有受控正文存储一份；快照失败不能触发另一套图片 fallback 写入。
- 从精简快照恢复时，描述应足以区分图片、文字、空图及待网络确认，不能因 icon 被精简误显示成“已删除”。
- 标准模式不建立新的对象图片副本；在线编辑、导出仍使用原数据/API，不能为了快照瘦身破坏备份或用户输入的 data URI。
- 旧快照中身份不明的图片不得直接迁入新副本；清理其已知旧图片字段并保持其他合法数据，不全 origin 清空。
- 快照恢复本身仍遵守当前数据访问边界；图标缓存不能让未获允许的私密书签重新出现在 UI。站点 custom_js/同源脚本可能访问本机数据，设备说明必须明确本功能不提供抵御 XSS、恶意扩展或本机取证的保密能力。

## 8. 二期分类图标开发计划

### 8.1 进入门与确定方案

一期的作用域、租期、预算和清理必须先通过，分类不得复制一套未稳定的缓存。只复用已工作的 descriptor/loader/storage 小接口，不新增信任开关、单独额度或通用资产平台。

IC-Q01 冻结采用 categories 增加与书签语义对齐的成功正文/内容版本/写入代次字段，继续使用 D1；复用现有类型化 descriptor、loader、IndexedDB 和联合预算。**计划基线时分类尚无这些服务端字段**，因此完整接入需要 Q02 服务端契约，不能仅给 loader 传一个 category 参数即声称完成。后续实现与剩余验收看 BACKLOG；具体契约见 §8.4，不另建数据库、信任开关或额度。

- `icon` 的文字/表情继续直接渲染；data URI 不额外发 HTTP，快照与正文避免双份。
- HTTP(S)/Iconify 仍是分类对象绑定；公共图片来源不意味着对象描述可匿名泄露。
- 外源同 URL 换图通过内容取得/刷新边界更新版本，不能按 URL 固定哈希充当正文版本；排序/导航布局不改变内容版本。
- 复用专用协议，增加 category 类型与现有祖先可见性规则；普通分类代理保持严格 no-store。
- 将 `CategoryIcon.svelte` 的持续退避重试改为协调层有界、受可见性/online 事件驱动的重试；保留最近成功图片，不在隐藏菜单持续请求。

冷/热基线按一个真实图片槽位定义。当前 `CategoryIcon` 的远程/代理图片每个独立挂载的 `<img>` 冷显示产生 1 次 `/api/category-icon/:id` 请求；data URI 没有独立图片 GET，但会随数据 API 传输。组件保持挂载且 source 未变时，Svelte 重渲染不增加请求；卸载后重新挂载会再发 1 次请求，因为普通分类代理客户端响应为 `no-store`，边缘缓存命中也不能消除浏览器请求。失败重试会按组件退避序列增加请求。该规则分别适用于下表入口；当前没有跨挂载去重或浏览器持久副本。

| 展示入口 | 冷态当前请求基线 | 热态保持挂载 | 离开后再进入 |
| --- | --- | --- | --- |
| Sidebar 顶部导航/子菜单/目录 | 每个已进入加载态的远程图标槽位 1 次代理请求；原生 lazy loading 决定何时开始 | 同一槽位 source 不变为 0 次新增请求 | 再挂载每槽位 1 次代理请求 |
| 分类范围与分类区域 | `HomeCategoryScope` 根/子项、`CategorySection` 标题各按挂载图像槽位 1 次；隐藏且未加载项为 0 | 已加载槽位 0 次新增请求 | 重新挂载的可见槽位各 1 次 |
| 搜索分组标题 | 每个实际渲染的远程分类标题图标 1 次；本地过滤不建立持久图片 | 搜索文本变化但同节点/URL 保留时 0 次新增请求 | 离开搜索或节点销毁后再创建，每槽位 1 次 |
| 后台分类列表 | 每个可见远程图标槽位 1 次，访问后台不会命中受控本地正文 | 同一列表保持挂载为 0 次新增请求 | 面板销毁后重开，每槽位 1 次 |
| 分类编辑/预览 | 未保存 data URI 只在内存，无新增代理 GET；远程来源按预览槽位 1 次 | 同一预览 URL 保持挂载为 0 次新增请求 | 重开预览对远程来源再请求；保存后目标列表仍按自身槽位取图 |

### 9.3 性能测量方法与判定

- 固定 100/500/1,000 书签数据、图片大小分布、可见性、滚动路径及网络条件；改前/改后分别测冷访问、暖访问、刷新、重开、首页↔后台、搜索、离线、单图变化、构建更新。
- 每场景至少 5 轮，报告可见图就绪时间中位数与尾部、正文请求/传输、D1 查询、存储操作、Blob/URL 持有数量；不只报告 HTTP 200 或 img.complete。
- HTTP 命中、SW 命中、应用持久命中、内存命中、edge HIT、失败/重试/取消分别计数；base64 网络膨胀与解码成本必须计入。
- 二访零正文只对“已成功暖机、当前权限有效、版本已知、尺寸合格、未被淘汰”的固定集合判定；必要版本请求单列。单图变更不连带下载其他图片。
- 缓存分为 shell/静态、公开快照、管理快照、对象正文、通用资源和元数据；分别报告字节/条目，保留既有各层门槛。原总量≤5 MiB 改为标准/可信模式可解释的分层检查，不粗暴改成一个更大总数。
- 索引序列化大小、实际孤儿正文、旧作用域残留与活跃内存单列；命中 N 图不能变成 N 次全库扫描。
- 性能无硬期限的指标先量化改前基线再评审允许变化；一条版本查询、已裁定预算和零未变正文不能通过调整统计口径放宽。

## 10. 迁移、发布和回滚门

### 10.1 升级矩阵

| 组合 | 要求 |
| --- | --- |
| 新客户端 + 旧服务端 | 不支持协议则标准展示；未知图片不落盘，不能缓存普通代理绕过 |
| 旧客户端 + 新服务端 | 原 API/聚合基础字段/代理行为兼容；不自动启用可信副本 |
| 新旧服务端写入并存 | 通过 §4.4 保护或关闭能力的切换门；不存在“正文新、摘要旧” |
| 旧标签 + 新标签 | 新版不认领旧副本；旧代码可能再次写旧命名空间，记录并在新版恢复/清理时重新清理；不宣称能控制任意旧代码 |
| 普通应用升级 | 新命名空间独立于 shell 指纹；compatible schema 图片保留，应用更新提示不受影响 |
| 一期升级至二期 | 原书签键及预算不变；加分类类型不要求全量重新下载书签 |
| 功能关闭 / 回滚 | 先封禁与清理，再关闭取得能力；兼容回滚包保留新命名空间清理和 legacy-write 保护 |

### 10.2 回滚方案必须在上线前验证

选定并保存可重建的兼容回滚版本（非临时口头承诺）：保留原展示路径，同时识别新 schema/命名空间、禁用可信使用、清理两期副本并阻止迟到写入。未完成设备要在再次打开兼容版本时执行清理；离线/永久不再访问的设备无法即时物理删除，不宣称全设备已擦除。

如采用清理桥接版本，必须验证旧标签、清理失败恢复、先清理后回滚的顺序；不能要求所有用户恰好访问过桥接页面才算安全。无法覆盖者使用长期保留清理逻辑的兼容回滚包。

D1 迁移以向后兼容新增字段为主，回滚不删业务数据/新列；不要用还原全库覆盖用户后续书签修改。安全开关关闭只影响副本能力，不改变普通代理权限和 no-store。

### 10.3 发布授权及文档同步

- 开发结果默认留本地。提交、推送、部署、Issue API 和 main 归档分别授权；本仓库 develop 推送可能触发自动部署，执行前需明确告知影响并检查目标。

- 同步 `docs/guides/PRODUCTION_ACCEPTANCE.md`、`TROUBLESHOOTING.md`、`scripts/README.md`；BACKLOG 仅记录实际状态，CHANGELOG 仅记录实际交付，不把规划写为已修复。
