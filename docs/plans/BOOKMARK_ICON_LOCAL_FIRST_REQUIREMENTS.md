## 阅读摘要

- 已裁定采用“标准模式 + 可信设备本地优先”，可信模式默认关闭；不直接回滚现有匿名图标隐私修复（IC-D01，2026-10-03）。已确认允许可信设备保存当前有效会话范围内的私密书签图标（IC-D02，2026-10-03）。
- 在可信且有效的会话作用域内，目标是普通刷新、同会话重开浏览器、未改图标的应用升级均不重复下载已缓存图片。
- 已裁定离线副本最多使用至最近一次成功联网认证校验后 24 小时，且不晚于会话到期；退出、检测到会话失效或撤销信任后立即停止使用并清理（IC-D03，2026-10-03）。对象图标正文上限已裁定为 10 MiB，条目、单图、索引与淘汰规则按第 4.3 节执行（IC-D04，2026-10-03）。
- 已裁定旧图标缓存不直接认领无法核实身份/版本的条目，升级后按需建立合规副本，不清空云端数据、不全库预热（IC-D06，2026-10-03）。
- 已裁定保留严格代理，可信副本另行会话鉴权取得，不兼容时安全降级，上线前准备可清理新版副本的兼容回滚方案（IC-D07，2026-10-03）。
- 图片版本、取得本地副本协议、会话清理和兼容回滚是实施前设计门；验收不能只检查“图片能显示”或“HTTP 200”。
- 已裁定分两阶段：第一阶段完整处理书签图标，第二阶段处理分类图标；第二阶段范围、依赖与 10 项专属验收见第 12.2 节（IC-D05，2026-10-03），规划确认不等于开发授权。
- 详细功能见第 5 节，失效规则见第 6 节，第一阶段 20 项验收见第 11 节，7 项开工裁定见第 15 节。

## 1. 背景与问题定义

### 1.1 用户问题

部署新版本后，用户发现大部分书签图标不再留在浏览器本地缓存，偏离了此前的核心体验目标：

> 已经成功加载过的书签图标，应尽量在本地直接复用；普通刷新、重新打开浏览器或升级应用，不应导致全部图标重新下载。网络暂时不可用时，已有可用内容应尽量保留。

这里的“本地”明确指当前设备、当前浏览器 profile 的持久存储，不指 Cloudflare 边缘节点，也不指 D1 中的 `icon_blob`。

### 1.2 已确认的原因

当前行为是策略变化，不应只按“部署后偶发丢缓存”处理：

1. `0ab39b9` 曾恢复本地优先：本地未命中后取对象代理图标，成功时保存本地，避免浏览器重开重复回源。
2. `b4e4f9f` 修复匿名对象图标的权限判断顺序：公开图标变私密后，不得先命中旧共享缓存再检查可见性。
3. `edb018b` 进一步解决实际部署环境的 Browser Cache TTL 覆盖问题，将对象图标客户端响应统一改为 `no-store`，升级 URL 版本、清理旧本地图标缓存，并禁止对象代理持久化。
4. 结果是：Cloudflare edge cache 仍可复用图片，但每次重新渲染通常仍要经过网络；前端取得的 `blob:` URL 只是当前文档使用的临时引用，不等于已持久化。

**本需求不是回滚隐私修复，而是在明确授权和撤回时效的前提下，恢复可控的本地优先体验。**

## 2. 目标、成功标准与非目标

### 2.1 核心目标

- **IC-G01 本地复用**：在允许持久化的模式和有效访问范围内，已缓存且版本未变的图标不重复下载。
- **IC-G02 升级稳定**：应用 JS/CSS、HTML、Service Worker 构建指纹变化，不自动等同于图标内容失效。
- **IC-G03 故障可用**：暂时断网、超时、429、5xx 不得用失败或文字兜底覆盖最近一次成功图标。
- **IC-G04 隐私分级**：普通访客的严格对象代理边界不回退；可信设备上的持久化必须明确告知并获得选择。
- **IC-G05 增量更新**：区分图片内容变化、访问权限变化与展示文案变化，只做必要更新。
- **IC-G06 容量可控**：本地副本有总字节、条目数、单图大小和清理规则，不能无界增长。
- **IC-G07 可解释**：用户能知道是否启用本地副本、占用多少、为什么不可用，以及清理的实际影响。

### 2.2 不在本轮范围

- 不改变书签分类、排序、导入导出业务语义，不重构整个数据层或后台设置页。
- 不将全部 `icon_blob` 塞回首页聚合接口，不首屏下载全库图标。
- 不要求安装额外服务、部署新存储产品或修改共享 Cloudflare Zone 的全局规则。
- 不保证浏览器清理站点数据、无痕会话结束、系统回收存储后仍保有缓存。
- 不承诺抹除用户已经复制、截图、导出或通过开发者工具保存的图片。
- 不新增“未登录查看私密书签”的能力；图标副本不得扩大页面数据本身的访问权限。
- 不默认支持匿名访客对可撤回书签图标的长期离线保存；若要求这一能力，须另行裁定更宽松的隐私模型。
- 分类图标缓存改造不属于第一阶段实现范围，但已明确纳入第二阶段规划，不能作为未排入范围的泛泛“以后优化”；详细边界见第 12.2 节。后台全量图标预热、跨设备同步图标缓存和自动压缩转码仍不在本轮必做范围。

## 3. 术语与不可兼得的边界

### 3.1 缓存分层

| 层级 | 当前/目标职责 | 是否等于本地持久副本 |
| --- | --- | --- |
| D1 `icon_blob` | 服务端最近成功图片的数据来源之一 | 否 |
| Worker `caches.default` | 权限检查后的共享网络响应复用 | 否 |
| 浏览器 HTTP cache | 浏览器依据 HTTP 策略管理，应用难以精确清理单一身份的数据 | 不作为可信私密副本的可控实现 |
| 应用管理的持久副本 | 明确作用域、版本、容量和删除规则的本机图片数据 | 是 |
| 当前页面 Blob / object URL | 供当前组件解码和展示，卸载后释放 | 否 |
| 数据快照 | 分类、书签、设置等轻量数据 | 不自动包含图片副本 |

### 3.2 两种“撤回”必须区分

1. **服务端停止新授权访问**：已改私密、已撤销会话的请求必须继续受到现有权限检查约束。
2. **撤回设备已经获得的数据**：在线客户端收到变化后可以隐藏、删除；离线客户端无法立即收到变化。

不能同时承诺“断网立即显示旧图标”与“远端一改权限，所有离线设备立即不能显示旧图标”。后台版本校验、内容哈希、短 TTL 均不能消除这个基本限制。

可信设备模式接受一个明确、有上限的离线旧状态窗口；标准模式不新增这种对象图标持久化能力。内容哈希仅用于识别内容，**不是访问凭据，也不是权限检查的替代品**。

## 4. 已裁定的产品模式与默认值

### 4.1 模式矩阵

| 场景 | 默认行为 | 持久化规则 | 离线行为 |
| --- | --- | --- | --- |
| 通用公共资源，如不承载对象隐私的 Iconify 公共资源 | 沿用可验证的资源缓存策略 | 只存成功、符合限制的资源；不因绑定到私密书签就缓存书签关联元数据 | 已缓存资源可用，但不得据此展示无权访问的书签 |
| 匿名访客的可撤回书签图标 | 标准模式 | 保持对象代理网络与权限边界，不写新持久副本 | 不保证对象图片离线恢复 |
| 已登录但未信任此设备 | 标准模式 | 对象图标仅当前会话运行时复用；不因登录自动落盘 | 沿用现有页面数据行为，不新增对象图片离线承诺 |
| 已登录且明确启用可信设备模式 | 本地优先 | 当前站点、当前有效会话作用域内可保存已授权图标 | 在离线租期、会话和数据快照共同允许的范围内展示 |
| 退出、会话失效、撤销信任、切换身份 | 禁止读旧作用域 | 立即封禁读取与写入，清理所属副本 | 不以“网络失败保留内容”为由继续显示已知无权访问内容 |

**已裁定：默认关闭“可信设备”**（IC-D01，2026-10-03）。匿名访客和未启用信任的设备保持标准模式；只有已登录且明确开启信任的设备才允许进入本地优先模式，不因应用升级自动开启。本方案不会让所有匿名访客都自动获得离线图标。IC-D01 仅确定默认策略与适用人群；私密副本范围与离线时效分别由 IC-D02、IC-D03 确认，容量预算另由 IC-D04 确认为 10 MiB 正文上限及配套限制。

### 4.2 会话与可信设备设置

**已裁定：允许可信设备保存私密书签图标，仅限当前有效登录会话作用域**（IC-D02，2026-10-03）。退出登录、检测到会话失效或撤销信任后，停止使用并清理所属副本；不同身份不能复用。该选择明确接受图片在本机落盘、并非加密保险箱，以及离线时无法立即接收远端撤回的限制；具体离线期限已由 IC-D03 确认为最长 24 小时，且不晚于会话到期。

- 可信设备选择只保存在当前 origin 的当前浏览器，不作为全站设置同步到其他设备，不进入站点备份。
- 首阶段图标副本与会话作用域绑定：正常关闭/重开浏览器、刷新页面，只要会话仍有效，应复用；退出后重新登录属于新作用域，不自动复用旧私密副本。
- 允许保留“本机偏好已选择信任”的配置，但必须先完成新会话初始化，不能把偏好当作认证。界面始终能撤销信任。
- 不使用用户名、书签 ID 或图标 URL 单独作为身份边界；用户名修改、同 origin 重装、账号切换和 ID 重用均须纳入处理。

IC-D03 的期限计算为 `min(最近成功联网认证校验时间 + 24 小时, 当前会话到期时间)`。正常联网且认证校验成功后重新计时；仅打开页面、本地命中、普通图片下载成功或请求失败不能续期。期限到达后暂停使用受该期限约束的图标副本，联网认证校验通过后才能恢复。退出、检测到会话失效或关闭可信模式时不等待期限，立即停止使用并清理；这与普通离线超期后的暂停使用相区分。

### 4.3 已裁定参数与实现建议

下表为已裁定的产品约束。**已裁定不等于已实现或已生效；实现调优不得自行放宽这些安全期限和容量限制**：

| 参数 | 已裁定值 | 说明 |
| --- | --- | --- |
| 对象图标持久副本总正文预算（IC-D04 已裁定） | 10 MiB / 当前站点可信作用域 | 10,485,760 字节；所有私密与公开对象副本合并计量，不允许多身份累加绕过预算 |
| 有效条目数（IC-D04 已裁定） | 1,000 条 | 与字节预算同时生效 |
| 单张图片正文上限（IC-D04 已裁定） | 512 KiB | 超限可按现有路径展示，但不保存，不要求首阶段转码 |
| 索引元数据上限（IC-D04 已裁定） | 512 KiB | 单独计量，不把 base64 图片计作“元数据” |
| 高水位淘汰目标（IC-D04 已裁定） | 正文预算的 80%，即 8 MiB | 达到容量或条目上限时优先淘汰最近最少使用的副本；正文超限时分批清理至该目标，并同时满足条目/索引上限，避免每次新增反复大清理 |
| 最大离线有效期（IC-D03 已裁定） | 最近成功联网认证校验后 24 小时 | 实际截止时间不晚于当前会话到期；仅打开页面、读本地数据或请求失败均不能续期 |

实现建议（不属于额外的产品裁定）：应用主动获取图片的并发可从 4 开始，在规模测试中确定；不篡改浏览器原生加载调度，不以调优为由改变已裁定的权限、租期和容量。

现有总 Cache Storage ≤5 MiB 等审计与上述“分层预算”存在差异。不能直接放宽总门槛掩盖增长；必须先拆分静态资源、数据快照、对象图标、通用资源和元数据的统计，再批准新预算。

## 5. 功能需求

### 5.1 IC-F01：本地优先展示

在可信模式和有效作用域内：

1. 组件获取图标描述，不直接访问持久存储或判断登录权限。
2. 协调层先核验本机模式、当前会话代次、数据快照和离线租期，再读取本地索引。
3. 精确内容版本命中时创建当前使用者独立 object URL，显示图片，不发该图片正文请求。
4. 缺失时显示稳定占位，按可见性需求获取一次真实图标；同图同作用域同版本合并在途请求。
5. 只有成功、解码可用、内容版本匹配且允许保存的图片才进入持久副本。
6. 本地命中不得先挂远程 `img` 再异步替换，避免已经命中仍多发一次请求。
7. 不主动预热尚未展示的全库书签；保留懒加载、异步解码、固定尺寸和低请求优先级。

### 5.2 IC-F02：统一真实调用链

首阶段至少覆盖：首页普通卡片、经常访问、搜索/Spotlight 结果、后台书签列表，以及编辑/显式刷新后的图标写入。IC-D05 已确认首阶段完整处理这些书签路径，分类图标暂维持现状；分类图标作为独立第二阶段按第 12.2 节实施和验收。

- 同一书签跨展示位置使用同一描述和策略，不允许一处公开、一处无条件带私密授权导致重复下载。
- 编辑弹窗预览未保存的图片可仅在内存存在；保存成功并取得当前版本后才更新持久副本。
- 当前 `applyLocalBookmarkIconBlob()` / `writeBookmarkIconDataUri()` 路径必须接入统一作用域和授权检查，不能成为绕过可信选择的第二写入口。
- 检查实体更新后是否把完整 `icon_blob` 又持久化进聚合快照；新图片副本原则上只有一个正文存储位置，不制造 localStorage + Cache Storage + 快照三份重复。
- 不将所有页面迁成一个巨大 Store；组件通过小接口申请和释放图标，不自行管理清理队列。

### 5.3 IC-F03：成功图标与失败兜底分离

- 网络错误、超时、408、429、5xx、带 `X-Icon-Fallback: 1` 的响应、HTML 错页和无效图片均不得更新“最近成功图标”。
- 瞬时失败保留已有成功副本，并沿用可见/online 等事件触发的有界重试；不得形成永久定时轮询或无限重试。
- “服务端明确清空图标”与“刷新失败没有拿到新图标”必须有不同结果，不能都用 `null` 覆盖旧图。
- 图标解码失败只剔除损坏条目，并进行一次受控修复；不能清空整个站点缓存。
- 401、403、已知删除或权限撤回不是普通网络失败：先停止旧内容展示，不走“保留旧图”的成功回退。

### 5.4 IC-F04：内容与访问权限分别版本化

至少区分：

- `content_revision`：实际图片内容版本；无图片、文字图标和未知版本应有明确表示。
- 数据集代次：同 origin 重装、替换导入或 ID 重用时隔离旧对象。
- 数据/可见性版本：书签私密状态、分类祖先关系、全站公开模式等访问规则变化。
- 本地会话代次：退出、401、身份切换时使旧异步工作失效。
- 图片存储 schema 版本：只有存储格式不兼容时迁移，不等同于应用版本号。

要求：

- URL 未变但图片正文变了，`content_revision` 必须变化；刷新得到同样字节时不制造新内容版本。
- 名称、描述、排序、卡片尺寸变化，不使相同图片失效；如果图片由标题生成，标题是生成输入，须重新计算该图片版本。
- 删除、显式清空、切换图标源与内容更新必须可靠发布变化；旧请求返回的版本不匹配时不能贴到新对象。
- 已知访问被撤回时，不得因 `content_revision` 未变而继续使用本地副本。
- 不把内容摘要放到无鉴权路径当作“拿到摘要就能读私密图标”的能力凭据。

### 5.5 IC-F05：刷新、浏览器重开与部署

- 未过期的同会话、同数据集、同内容版本，在常规刷新和浏览器重开后应复用本地副本。
- 普通前端部署只淘汰旧应用 shell/chunk，不批量删除可兼容的图标副本。
- 图标 schema 迁移独立执行；失败应保留可解释的降级状态，不能阻塞首页。
- 不把 DevTools “禁用缓存”、强制刷新、站点数据清理或新 profile 与普通二访混为同一验收条件。
- 应用更新提示仍按现有机制运行，不以持久图标缓存阻止新版本加载。

### 5.6 IC-F06：增量新鲜度确认

- 复用现有数据版本刷新和焦点/可见性恢复入口，不另起一套固定轮询。
- 未变化时不重取全量图片；仅一次文字、排序或无关设置修改，不应下载所有书签图标。
- 版本变化后通过轻量描述找出删除、权限变化和内容变化，只处理差集；聚合响应不得附带全量图片正文。
- 冷启动中允许可信设备先用租期内快照和图片，再后台确认；这是明确接受的陈旧窗口，不得声称已实时认证。
- `/api/data/version` 失败时保留仍处于许可范围内的数据；成功得到当前权限或版本结果后必须立即执行失效逻辑。
- 后台网络成功但未完成有效认证、普通图片 edge HIT、读取本地快照，都不能延长离线租期。

### 5.7 IC-F07：退出、跨标签页与异步竞态

- 退出/401/撤销信任时先改变访问代次并停止读写，再删除副本和释放 object URL；不能先等待清理完成才阻止展示。
- 所有写入携带开始时的作用域与代次；响应返回、解码完成、持久化提交后均须校验，旧工作不能使已清理副本“复活”。
- Cache API 写入不可取消时，必须在串行清理边界或等效机制下删除迟到结果；事件发生在其他标签页时也要成立。
- 复用既有存储/会话通知能力；只有它不能覆盖时才增加单一跨标签页通知通道，不并存多个无主的同步机制。
- 本标签退出立即停止展示；活动的同 origin 其他标签收到通知后处理，冻结标签在恢复时先检查代次再允许读取。
- 到达会话或离线租期截止时间须停止使用私密副本；可用一次性到期调度，不增加周期轮询。时钟倒退或有效期数据异常时保守拒绝离线访问。
- 清理失败应报告“已停止使用，磁盘清理未完成”，重试前不得重新开放旧作用域。

### 5.8 IC-F08：可操作的设备级设置

建议在现有后台合适位置加入小型“此设备的图标缓存”区域，不混入全站视觉设置：

- 开关：**“在此设备保留书签图标”**，默认关闭。开启只保存偏好，提示下次完整刷新或重新打开页面后生效；当前页面与已打开的其他页面不立即切换图标路径，返回首页、切换面板或联网校验也不提前激活。关闭仍立即停用并清理，重新开启同样延迟生效。
- 说明：只影响此浏览器；会保存当前登录范围内的图片，可能包含私密图标；不应在共用电脑启用。
- 离线说明：可显示最近成功副本，远端撤回无法立即到达离线设备，离线有效期有上限。
- 状态：未启用、已启用、空间不足、存储不可用、离线租期已到期、清理失败。
- 指标：有效条目数、图片正文字节、上限和最近成功校验时间，不展示内部 URL、Token、私密图片清单。
- 操作：“清理此设备图标副本”“关闭并清理”；明确不删除云端书签和 D1 图标。
- 清理不等于刷新全站图标：当前可见图标按需重新获取，不后台自动重建全库。
- 状态反馈非阻塞且可由辅助技术读取；键盘可操作，移动端不产生横向溢出或遮挡确认按钮。

## 6. 缓存与失效契约

### 6.1 唯一正文存储

首选沿用现有 Cache Storage 能力保存应用管理的图片正文，并使用轻量索引；不为本需求先引入存储依赖。

但必须满足以下条件，否则在设计评审中选择 IndexedDB 作为**替代**，不是再加一份镜像：

- 能维护总大小和条目数，处理多标签页并发，不每命中一张图片就扫描/读取全部图片。
- 能恢复正文与索引不一致、部分写入和 quota 失败。
- 能完成作用域级清理、迟到写入防护、LRU 和 schema 迁移。
- 不将大量 base64 正文长期写入同步 localStorage。每个正文只能有一个主要持久化后端，fallback 也不得同时双写。

### 6.2 作用域与索引

建议的逻辑身份为：

`站点 origin / 数据集代次 / 会话作用域 / 对象类型 / 对象 ID / 内容版本`

这只是职责定义，不要求 URL 按此字面拼接。要求：

- 会话作用域复用现有认证缓存隔离思想，必须抗不同会话碰撞；新索引不保存原始 Token、密码、短期图标 key 或完整带凭据 URL。
- 索引至少有内容版本、类型、正文大小、最近使用时间、成功保存时间、作用域和 schema；不额外复制标题、账号名称或书签目标地址。
- 同一当前作用域内允许按内容摘要消除重复正文，但必须保留每个对象的授权引用；首阶段不做跨身份/跨站点正文共享。
- 失去最后一个有效引用后才回收共享正文；权限收紧后立即撤销对应引用，不能被别的对象重新授权。
- LRU 最近使用记录允许有界合并写，不能每次组件响应式更新都落盘。

### 6.3 失效矩阵

| 事件 | 当前显示 | 持久副本处理 | 网络行为 |
| --- | --- | --- | --- |
| 页面刷新、浏览器重开，会话和租期有效 | 本地优先 | 保留 | 复用版本检查；未变正文零下载 |
| 普通应用部署，图片 schema 兼容 | 保留图标 | 不按构建指纹删除 | 只更新应用资源和必要元数据 |
| 图标内容变化，当前用户仍有权 | 可暂时显示旧成功图 | 新图验证成功后替换；限制旧版本保留 | 只取变化且当前需要的图片 |
| 图片刷新超时/429/5xx | 保留许可范围内成功图 | 不写错误/兜底，不延长租期 | 有界重试 |
| 显式删除或清空图标 | 不继续显示旧图 | 删除对应引用与无引用正文 | 不用失败回退恢复它 |
| 公开转私密、祖先分类变私密 | 重新按当前身份判定 | 无权者清除；仍获授权的管理员可保留于可信作用域 | 先确认访问，不按“曾公开”放行 |
| 分类移动、公开模式关闭 | 同上 | 检查有效祖先链和最终可见性 | 不只检查书签自身 `is_private` |
| 退出、401、身份切换、撤销信任 | 立即停止旧作用域使用 | 清理并防迟到写入 | 禁止旧凭据工作继续写 |
| 远端撤销，设备离线 | 租期内按已同意边界使用 | 到期停止读取；恢复后以服务端结果为准 | 不宣称立即撤回 |
| 导入替换、重装、ID 重用 | 不混用旧对象 | 数据集代次隔离，清理旧代次 | 必要时重新取得描述 |
| 用户清理/浏览器驱逐 | 按需占位与恢复 | 不影响服务端数据 | 只加载当前需要图片 |
| 存储满/禁用 | 内存或原展示路径降级 | 淘汰或拒绝本次保存，不崩溃 | 不因无法落盘而循环下载 |

## 7. 数据与 API 需求

### 7.1 保持的现有契约

- 聚合数据保持轻量；`icon_cached` 继续只表示服务端是否报告存在缓存，不冒充客户端命中状态。
- 匿名对象图标在每次共享 edge lookup 前执行权威可见性检查，未知、孤儿、循环和私密对象继续 fail closed。
- `/api/icon/*`、`/api/category-icon/*` 的现有 `no-store` 与 Service Worker 不接管行为，不因本地副本需求直接删除。
- 短期 `icon-access` key 与登录会话不是同一权限契约；当前 key 有自身有效期和撤销限制，不能用它续期本地可信访问。
- 不把授权 key 写入本地图片索引、日志、持久请求 URL 或导出的诊断文件。

### 7.2 需要补齐的轻量描述

以下字段是**逻辑需求示意，不是当前已存在的 API**。最终命名与放置由接口设计确定，优先扩展已有响应而不是增加启动请求：

| 信息 | 用途 | 约束 |
| --- | --- | --- |
| `content_revision` | 判断正文是否变化 | 不用应用版本、标题哈希或 `icon_cached` 替代 |
| 数据集代次 | 防止重装/导入后 ID 碰撞 | 不作为认证凭据；替换导入必须变化 |
| 描述与数据版本的对应关系 | 确认同一份元数据 | 不允许旧描述覆盖新权限结果 |
| 图片是否可取得、是否被明确清空 | 区分无图与失败 | 对无权对象不泄露私密图片摘要/存在性 |
| 成功认证校验所需有效期信息 | 计算本地租期 | 来自现有有效认证流程，不从图片成功推断 |

匿名接口只返回其允许知道的对象信息；完整私密描述只能出现在经过会话鉴权的响应内。内容版本应在写入图片时计算/维护，不在每次聚合读取时扫描和散列所有图片正文。

### 7.3 可信本地副本的取得协议

**已裁定原则（IC-D07，2026-10-03）**：保留现有严格代理；可信副本采用经过会话鉴权的专用取得协议，客户端确认可信选择、有效作用域和内容版本后才保存成功图片；不兼容时只按既有方式联网展示，不保存权限或版本不明的副本。上线前必须备好能够清理新副本的兼容回滚方案，不承诺任意旧版本可直接安全回滚，也不依赖修改 Cloudflare 全局缓存规则。以下条款细化该原则，具体接口设计仍需评审。

**不能把 `no-store` 拒收判断删掉，也不能给普通代理加一个前端参数就视为获准持久化。**

需要在接口评审中明确一个仅用于可信模式的、经过会话鉴权的“取得本地副本”协议：

- 只读取得当前对象已授权的成功图片和内容版本，不触发用户未要求的全库刷新。
- 权限依据服务端认证，不依赖客户端声称的 `trusted=true`、内容摘要或曾经公开状态。
- 本机可信选择是客户端允许保存的必要条件；服务器仍必须验证读取权限。
- 传输响应禁止进入共享 edge 和不可控浏览器 HTTP 缓存；应用只在授权保存语义明确时，将验证后的图片数据写入受控存储。
- 区分“HTTP 响应不被自动缓存”和“用户明确选择保存的应用数据”：若传输使用 `no-store`，该专用下载/物化协议必须明确允许应用保存其图片数据；**普通代理的任意 `no-store`、私密预览或错误响应仍不能走此例外**。不得把原始响应整份克隆到普通 URL cache。
- 可以采用受保护的数据响应携带图片内容和版本；不得把本地副本白名单逻辑推广到所有 API。传输编码、图片 MIME、内容长度和解码验证必须有确定规则与独立测试。
- 服务端缺少该能力、返回未知协议版本、版本不匹配或 `deny` 时，降级为现有网络展示，不退回到直接缓存普通代理。
- 返回的图片版本必须与真实正文一致；旧请求撞上新描述时返回可识别的版本冲突或当前描述，前端不得错存旧键。

本节是必须完成的接口设计门，不要求本轮提前确定路由名称。首阶段不强制引入批量端点；如果增加批量，须限制条目数、字节、并发与每项权限，并证明比单项协议更有价值。

### 7.4 D1 与一致性

- 当前 `setIconBlob()` 直接更新 `icon_blob`，本身不维护图片版本；不能假定所有调用已自动发布新鲜度信息。
- 开发前列举显式刷新、保存、导入、代理按需补全、清空/损坏恢复等所有写入入口，确定谁负责计算内容版本与发布变化。
- 图片正文与版本须在同一原子更新边界一致；并发抓取旧 URL 不得覆盖用户刚保存的新图标。
- 惰性补全不得每张图都触发其他标签重新拉全量数据的请求风暴；区分“首次补全描述”和“替换已发布内容”，设计可收敛的发布规则并测试。
- 若新增字段，迁移须幂等、兼容旧库；不在首个首页请求同步处理全库图片。未知版本宁可暂不持久化，不能伪造稳定版本。
- 不把本机可信设置或缓存条目写入云端设置和站点备份；服务端版本字段的导入策略需防止备份中的旧值污染当前数据集。

## 8. 模块职责与依赖约束

下列名称表示职责；除已存在路径外不要求机械创建同名文件。

| 模块/层 | 所有权与职责 | 不应承担 |
| --- | --- | --- |
| `shared/` 图标描述契约 | 模式枚举、版本描述、成功/拒绝/失败语义 | DOM、Cache API、数据库访问 |
| Worker D1 访问层 | 图片正文/版本的原子读写、数据集代次 | 页面组件和本机可信开关 |
| Worker 路由编排 | 鉴权、可见性、取得成功内容、传输策略 | 客户端离线租期与设备 LRU |
| 前端纯策略模块 | 给定身份、模式、版本、租期后的允许读写/失效决定 | 直接读 localStorage、发请求、操作 DOM |
| 本地存储适配器 | 正文/索引读写、容量、LRU、清理队列与恢复 | 网络请求、页面提示、登录 UI |
| 图标获取协调层 | 调用策略、存储、网络；在途去重、并发、代次检查 | 书签 CRUD、全局设置编排 |
| 会话/数据服务 | 会话代次、版本同步和失效通知的唯一来源 | 按卡片独立发起轮询 |
| 展示组件 | 接收图标展示结果、局部 loading/error、释放使用权 | 独立持久化、推导其他页面的权限 |
| Service Worker | 应用 shell、静态资源与明确公共资源 | 自动截获私密对象并恢复 cache-first |

依赖方向：UI → 协调层 → 纯策略/存储适配/API；Worker 路由 → 业务规则/数据访问；共享描述不反向依赖 UI 或基础设施。

关键可变状态只有一个所有者：可信模式与会话代次由会话/设备设置边界持有；正文索引与预算由存储适配器持有；在途任务与使用者引用由协调层持有。组件不得直接修改这些全局状态。

需结合实际接入点检查：`BookmarkCard.svelte`、`CachedBookmarkIcon.svelte`、`SpotlightBookmarkIcon.svelte`、`localBookmarkIconCache.ts`、`bookmarkCardIconState.ts`、`dataService.ts`、`adminDataCache.ts` 和 `iconAccessKey.ts`。新模块单测通过但未替换这些生产调用，不能算完成。

## 9. 兼容、迁移与回滚

### 9.1 本地旧数据迁移

- 当前 `v1` 已删除的正文无法凭空恢复，只能再次按需下载。
- 旧 `v2` 和 `cf-navs.bookmark-icon.*` 中可能有无身份作用域、无内容版本的数据，不能直接认领为新可信副本。
- **已裁定（IC-D06，2026-10-03）：不直接继承无法核实身份归属和内容版本的旧图标缓存。** 只清理确认属于本应用的旧图标命名空间，不删除云端书签、云端图标或设置，不清理其他站点数据；不得调用全 origin `caches.delete`/`localStorage.clear` 来顺手清理其他内容。
- 首次升级允许重新获取当前需要的图标并建立合规副本，不全库预热、不要求用户逐条手动刷新；建立后按已裁定的本地优先规则复用，普通刷新和应用升级不得继续反复删除有效的新副本。
- 普通应用更新保留新 schema 的图标；真正不兼容时才执行幂等迁移，损坏条目按条处理。
- 旧标签页可能继续运行旧写入代码，必须覆盖其与新版本并存的窗口；不能只在“全新 profile”证明迁移成功。

### 9.2 服务端/客户端混合版本

- 新客户端连接旧服务端：能力缺失则标准模式展示，不持久化不明语义的图片。
- 旧客户端连接新服务端：原代理与聚合基础字段保持兼容，旧客户端不自动获得可信副本能力。
- schema 迁移和正文版本应允许灰度读取，不能让旧代码写入后留下与正文不一致的版本。
- 回滚到旧前端时，新私密副本不能成为“代码不认识所以永不清理”的遗留数据。发布前必须选择并验证：保留能清理新命名空间的兼容回滚包，或先发布清理桥接版本；不得承诺任意旧版本直接回滚安全。
- 不回滚匿名权限门以换取缓存命中率；可信功能可独立关闭，普通浏览继续可用。

## 10. 性能与观测要求

### 10.1 场景与指标

| 指标 | 目标/约束 |
| --- | --- |
| 可信模式、稳定 fixture、全部合格图标已成功暖机，普通二访 | 未变图标正文网络请求 0、传输 0；不把必要的版本请求算图标正文 |
| 同会话重开浏览器、未超过租期 | 同上；必须使用同一测试 profile，不能新建 profile 冒充二访 |
| 修改一个图标 | 只下载该内容及真实必要依赖，其他未变图片零下载 |
| 未改图标的应用升级 | 不批量重新下载图标；应用资源下载另计 |
| 同图跨卡片/经常访问/搜索展示 | 同一作用域同版本的在途正文请求最多 1 个，使用者释放互不影响 |
| 权限更新后无权对象 | 不以本地命中优化绕过失效 |
| 首访请求 | 不因本地持久化再追加一遍相同图片下载，记录全部实际请求来源 |
| 数据版本检查 | 不增加固定轮询，不增加每图一条版本查询；保留现有一条 D1 查询目标，若必须改变须另行评审 |
| 正文/索引/运行时内存 | 分别记录；组件卸载释放 Blob，退出清理后索引与正文可回收 |

“合格图标”指当前可显示、权限有效、真实成功、大小在限额内、版本已知且未被浏览器驱逐的图片。不得把错误图标、超限图标或未访问图标偷偷计入本地命中分母。

### 10.2 测量方法

- 稳定合成数据至少覆盖 100、500、1,000 条书签，以及少量/大量超限图；固定可见性、图片大小分布、网络条件与滚动路径。
- 对比现有实现与新实现的冷访问、暖访问、刷新、浏览器重开、首页→后台→首页、搜索恢复、断网、应用升级和图标变化。
- 分开统计浏览器 HTTP 命中、应用持久命中、内存命中、edge 命中、正文下载、兜底、重试、取消；不能只看 `img.complete` 或 HTTP 200。
- 记录可见图片就绪时间的中位数与尾部情况，至少重复 5 轮；避免把任意固定等待当作成功依据。
- 记录本地存储操作数；命中 N 张图不应退化成 N 次完整缓存遍历或所有图片正文解码。
- D1 查询量通过可控测试环境日志/指标测量，不能由 `CF-Cache-Status: HIT` 推断零数据库查询。
- 更新审计时保留原有覆盖，增加分层预算与模式标签，不删除安全用例来使新缓存“通过”。

## 12. 实施顺序与交付门

IC-D05 已明确两个产品交付阶段：**第一阶段书签图标，第二阶段分类图标**。下面的 A～E 是第一阶段内部的实施步骤，不是把“阶段 B”误当成分类图标第二阶段。此处记录范围与交付门，不维护开发进度，不构成开发、提交或部署授权。

各步骤完成后按仓库规范单独验证，并在得到用户授权后提交，不将多个独立主题长期堆在工作树。

### 12.1 第一阶段：书签图标完整链路

#### 步骤 A：裁定与协议设计

- 将 IC-D01～IC-D04 已裁定的模式默认值、私密副本范围、租期和容量落实为契约与测试前提。
- 定义内容版本、数据集代次、鉴权物化协议、混合版本与回滚方案。
- 列举全部正文写入入口，评审数据库一致性和惰性补全收敛问题。
- 交付：契约设计、基线 fixture、可失败的验收用例；未通过设计门不编码持久化例外。

#### 步骤 B：内容版本与服务端边界

- 幂等补齐版本与读取契约，保留现有代理安全门和轻量聚合。
- 验证并发更新、清空、无权请求、旧客户端和部署平台头部行为。
- 交付：生产可接入的服务端契约及 L0/L1 证据，不宣称本地优先已完成。

#### 步骤 C：可信存储与会话生命周期

- 先实现可独立测试的纯策略、作用域、预算、清理和竞态保护。
- 接入设备选择、会话代次、租期和跨标签通知。
- 完成只读降级与清理失败提示，不引入全库预热。

#### 步骤 D：接入全部图标使用路径

- 首页、经常访问、搜索、后台、编辑刷新逐一接入，处理原始 data URI 和聚合快照重复存储。
- 每接入一条关键路径即验证，不保留未使用的“备用缓存实现”。
- 交付：稳定 fixture 的二访零未变正文请求、失败保留与退出清理的真实浏览器证据。

#### 步骤 E：迁移、性能、文档与发布验收

- 测试旧缓存/旧标签、配额与规模、升级保留和兼容回滚。
- 同步 API/性能/技术说明、故障排查和生产验收脚本，明确两种模式不同门槛。
- 用户另行授权部署后验证实际入口，不只测构建或预览地址；两次部署场景未执行时保留为未验证项。


### 12.2 第二阶段：分类图标本地优先

本阶段是 IC-D05 指定的后续交付范围，不是未承诺的可选优化；当前只确认并细化规划，开发须另行授权。第一阶段完成报告必须明确分类图标仍按原策略运行，直到本阶段独立通过验收。

#### 12.2.1 进入条件与第一阶段需要留好的边界

- 第一阶段的可信模式、会话/租期、正文版本、存储预算、退出清理与专用副本取得协议已通过相应验收；旧缓存按已裁定的 IC-D06 按需重建，副本取得与回滚遵守 IC-D07；不能以扩展分类对象为由放宽已确认的鉴权与清理边界。
- 本地索引从第一阶段就包含对象类型，避免同 ID 的书签和分类碰撞；作用域与总预算不能写死为书签页面内部状态。
- 纯缓存策略和存储适配器不依赖 BookmarkCard 或书签实体的全部字段，第二阶段通过分类描述适配接入。
- 不为此提前提交未接入生产路径的分类模块、备用路由或通用资产框架；第一阶段只保留真实需要的小接口和稳定边界。
- 若第一阶段仍存在跨身份、迟到写入或退出清理缺陷，先修复共享边界，再扩展分类对象，不能复制一份有同样问题的存储实现。

#### 12.2.2 真实现状与差异

源码核对表明，分类并不是改一个类型参数就能直接套用书签实现：

| 当前实现 | 第二阶段必须处理的差异 |
| --- | --- |
| Category 只有 icon 等字段，没有书签的 icon_blob/icon_cached 结构 | 明确分类成功图片的内容版本和来源，不能假装已有持久化正文与版本字段 |
| categoryIconDisplay.ts 的 getCategoryImageIconUrl 将 HTTP(S)/Iconify 分类图片转为对象代理 | 不以“来自公共图标库”绕过分类对象的身份与祖先可见性；公共资源缓存与对象绑定信息分开 |
| /api/category-icon/:id 经可见性检查后取 edge、data URI 或外源图片，普通路径没有书签式 D1 正文写入 | 定义稳定正文版本；不能因 edge 驱逐或浏览器重开就失去内容身份，也不在每次元数据请求重新抓全量外源图 |
| CategoryIcon.svelte 自持失败 URL、计数与定时器，退避封顶后仍可持续重试 | 迁入统一的有界重试与最近成功副本回退，不在隐藏导航/离线期间持续请求；该行为改造属于第二阶段 |
| data URI、文字/表情与图片共用分类 icon 字段 | 文字/表情仍直接渲染，data URI 不增加多余 HTTP 请求，也不制造快照与图片存储的重复正文 |

分类正文和版本最终采用分类专有字段还是已有类型化存储边界，须在本阶段设计门中基于第一阶段实现确定；不得为分类提前创建一套无人维护的独立图片数据库。对外导入导出格式保持兼容，内部版本不信任备份中的旧值。

#### 12.2.3 功能与调用位置

分类图标应接入同一可信设备选择、当前会话范围、24 小时离线期限、退出清理和失败策略，不新增“分类专用信任开关”。

至少覆盖下列现有调用：

| 位置 | 当前接入文件 | 要求 |
| --- | --- | --- |
| 顶部导航一级项、子分类菜单 | Sidebar.svelte | 重复展示合并请求；展开已缓存子分类不再下载正文 |
| 左侧导航、目录及子分类项 | Sidebar.svelte | 切换导航布局复用同一图片，不因尺寸/布局变化失效 |
| 首页分类标题与分类区域 | CategorySection.svelte | 与导航中的相同分类共享副本，不重复落盘 |
| 分类范围和子分类切换区域 | HomeCategoryScope.svelte | 切换可见范围只按需读取，不预热所有隐藏分类 |
| 首页搜索分组标题 | Home.svelte | 搜索出现/消失不重复下载已缓存分类图片 |
| 后台分类列表 | admin/CategoryListPanel.svelte | 公开与私密分类正确分流，不能无条件以私密授权获取公开对象 |
| 分类编辑、保存与预览 | 分类表单及其回调，实施前逐一核对 | 未保存预览不污染；保存后当前名称/图标/权限状态在导航与列表一致更新 |

空图标、文字、表情、data URI、HTTP(S) 与 Iconify 的显示语义保持兼容；缓存回退不改变分类名称、层级与可访问性语义。保留尺寸、对齐、loading 属性和装饰性图标的读屏处理。

#### 12.2.4 协议、版本、权限与容量

- 可信分类副本通过第一阶段确定的受保护协议取得；普通分类代理继续 no-store，Service Worker 不恢复 /api/category-icon/* 的无条件 cache-first。
- 分类内容版本来自成功图片正文或确定的生成输入；同 URL 换图要更新，改排序/导航位置不更新无关图片。分类名称只在影响生成图内容时参与版本。
- 元数据尽量随已有分类/聚合数据返回，不新增每分类一个版本请求；相同图片的多个导航入口不得分别做内容版本查询。
- 本分类、祖先链、全站公开模式共同决定有效可见性；私密→公开、公开→私密、换父分类、删除父分类和异常祖先链均需覆盖。
- 无权分类不得泄露摘要、图片存在性或私密名称；原授权 key 的有效期不替代本地会话期限。
- 删除/清空分类图标只删除该分类引用，不能误删同 ID 书签；内容共享时遵守引用回收规则，不跨身份共享正文。
- 第二阶段默认沿用已裁定预算：**书签 + 分类合计 10 MiB 正文、合计 1,000 条有效条目、合计 512 KiB 索引；单图 512 KiB，正文高水位淘汰至 8 MiB**。不能为分类另开一份 10 MiB 或 1,000 条额度；如实测不足，单独提请调整。
- 设备设置显示合计使用量，可补充书签/分类子计数；原清理按钮清理当前作用域两类对象，标签必须说明范围，不保留“只清书签、私密分类遗留”的缝隙。
- 分类无效内容、存储故障和超限均按统一策略降级；失败图片不落盘，已有成功图在许可范围内保留。

#### 12.2.5 实施顺序与交付物

1. **分类基线与描述设计**：核对上述调用、祖先可见性、data URI 快照路径与现有重试，记录冷/热请求量；确定分类内容版本和受保护取得协议的扩展方式。
2. **服务端能力**：实现分类描述、版本一致性及权限边界；必要迁移幂等，旧客户端可继续访问原代理，匿名存在性防护不回退。
3. **分类适配接入**：CategoryIcon 通过协调层获得展示结果；逐一验证导航、分类区域、搜索、后台和编辑保存，不再由每个入口另建缓存或重试循环。
4. **联合资源与生命周期**：验证书签/分类共享容量、类型隔离、并发写入、退出、多标签清理和旧版本回滚；分类扩展不能造成第一阶段图标全部重新下载。
5. **第二阶段独立验收**：跑下表及第一阶段受影响回归，更新契约与审计；获授权部署后验证实际入口，明确未覆盖的环境差异。

第二阶段交付物包括分类契约、真实调用链实现、迁移/兼容方案、增补测试与分层性能证据，不以“复用组件已经创建”代替已接入、可恢复和可清理。

#### 12.2.6 第二阶段专属验收

以下 IC-C* 为分类阶段验收编号；共享安全场景继续复用第 11 节，不另造第二套较宽松标准。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| IC-C01 | 同一分类同时出现在顶/侧导航、首页、搜索和后台 | 同作用域同版本复用副本，未命中时合并在途正文请求，无每位置单独落盘 |
| IC-C02 | 可信暖机后刷新/同 profile 重开浏览器/租期内断网 | 已缓存合格分类图片恢复，未变正文零下载；租期到期和权限失效不继续读取 |
| IC-C03 | 一级/子分类改私密、换父级、删除祖先、异常祖先链 | 正确按最终可见性处理；未知/无权分类无存在性泄露，匿名旧缓存不能绕过服务端门 |
| IC-C04 | 改分类图标、同 URL 换图、清空、改名、排序/布局切换 | 内容变化只失效相关图片；显式清空不恢复旧图；无关布局变化不清空副本 |
| IC-C05 | 文字/表情/data URI/HTTP(S)/Iconify/损坏内容 | 显示语义保持；本地可用内容不多发 HTTP；损坏或兜底不写成功副本 |
| IC-C06 | 503/429/超时/断网及隐藏导航 | 最近成功图保留；请求有界，不继续无限定时重试；online 恢复不形成请求风暴 |
| IC-C07 | 书签和分类同数字 ID、相同图片、合计超过预算 | 不串图、不串权限；联合容量遵守 10 MiB/条目/索引上限，引用回收正确 |
| IC-C08 | 分类下载过程中退出/撤销信任，其他标签同时写书签 | 两类对象一起停止旧作用域读写，清理后无迟到复活和分类残留 |
| IC-C09 | 从仅支持书签的版本升级，再执行兼容回滚 | 兼容书签副本保留；分类副本可清理；普通应用构建变化不批量下载两类图片 |
| IC-C10 | 桌面/窄屏、顶部/侧边布局、菜单展开、键盘/读屏 | 图标大小与导航命中区不退化，文字回退和辅助技术语义正确，无布局跳动导致的操作遮挡 |

稳定混合 fixture 至少包含 100 条书签、30 个合法层级分类，覆盖公开/私密、重复内容与各来源；另设超过联合预算的规模 fixture 验证淘汰，不对被容量策略淘汰的图片宣称零请求。记录书签与分类各自正文请求、持久命中、占用和重试，同时报告联合总量。

## 14. 风险与防误解清单

| 风险 | 必须采取的约束 |
| --- | --- |
| 可信模式被理解为默认公开缓存全部图片 | 默认不自动开启，界面明确包含私密副本及离线撤回限制 |
| 为兼容共享域名缓存规则而放松 no-store | 保留原代理；独立评审可信物化协议，目标环境验证无共享/不可控 HTTP 缓存 |
| 本地存储被当作加密保险箱 | 同 origin 脚本及有本机权限者可能访问；不声称抵抗 XSS、恶意扩展和物理取证 |
| 站点 custom_js 能读取同源数据 | 沿用站点已有脚本信任边界，风险说明不把 trusted 模式包装为额外保密能力 |
| 标准模式只阻止新图片副本，但旧快照已有 data URI | 明确审计已有写入口和快照，不以“对象代理未缓存”推断整个浏览器没有私密图片 |
| 只加内容摘要、不验证权限 | 摘要不得成为私密下载能力；未知/无权对象不得泄露版本或图片存在性 |
| 退出清理与旧异步结果竞态 | 代次校验、串行/等效清理与多标签验证缺一不可 |
| 缓存条目很少但内存不断增长 | object URL 引用释放与正文容量分别验收 |
| 修改审计预算掩盖回归 | 先做分层测量、批准预算，保留旧安全场景和冷访指标 |
| 私密副本被清理但浏览器原始 HTTP 缓存仍在 | 可信图片传输禁止不可控缓存，不能仅验证应用 Cache Storage 已空 |
| 两次部署或旧浏览器场景没测却宣称完整完成 | 最终交付逐项区分验证层级和残余风险，不由 L0 推断生产行为 |

## 16. 完成定义

以下为第一阶段书签图标的完成定义；第二阶段分类图标还须独立满足第 12.2 节，未完成前不得宣称所有对象图标均已恢复本地优先。

只有同时满足下列条件，才能宣称“书签图标本地优先缓存已恢复”：

1. 模式、隐私边界、预算和协议已裁定，当前参考契约与实现一致。
2. 真实首页/后台/搜索/编辑路径均按范围接入，不存在绕过策略的旧写入口。
3. 已缓存且版本未变的合格图片，在可信模式刷新和同会话浏览器重开时零正文下载。
4. 许可范围内离线可恢复，瞬时失败不污染最近成功副本，已知无权状态不复用旧图。
5. 普通应用升级保留兼容图标，内容更新只失效相关对象。
6. 匿名可见性、私密授权、会话清理、跨标签竞态、ID 重用和混合版本测试通过。
7. 容量、索引、内存引用与网络/D1 成本都有可比较的测量，不靠删测试或放宽未批准预算过关。
8. 文档、测试与审计脚本同步；未验证的两次部署、浏览器差异和平台缓存规则明确列出。
9. 测试会话、profile 和临时资源按所有权清理，敏感数据未进入仓库。
10. Git 提交、推送和部署仅在对应授权下执行；没有授权时交付本地工作树和验证结果。
