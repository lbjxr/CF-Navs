## 历史观察与证据边界

当时报告的现象是：鼠标悬停一张信息卡片时，相邻卡片底部似乎出现彩色反光。
原调查使用 ffmpeg 和 Python 图像差分，对悬停前后画面及相邻区域进行比较。
录屏、逐帧产物和原始调查稿保留在仓库外，不包含在本文中。

原调查记录报告了以下结果：

- 排除鼠标光标后，可见变化主要集中在被悬停卡片自身的上、下边缘。
- 相邻卡片与卡片间隙在差分阈值大于 20 的区域统计中，变化像素数为 0。
- 以每秒 2 帧采样时，相邻区域的最大像素差值为 4～8；原调查将其判断为视频压缩噪声。
- 隔离浏览器中的截图与样式对照探针没有稳定复现相邻卡片反光。

这些结果只支持“在当时选取的画面、区域和环境中未检出相邻反光”。
它们不能排除其他浏览器、主题、缩放或 GPU 合成条件下的问题，也不能替代当前版本的行为验收。

## 源码核对与保留约束

- [BookmarkCardInfo.svelte](../../src/components/BookmarkCardInfo.svelte) 的
  `.bookmark-card-info:hover` 会改变被悬停卡片自身的描边和阴影；暗色主题覆盖规则将描边设为
  `rgba(125, 211, 252, 0.32)`。这与原调查描述的青色边缘变化相符，但不是运行验证。
- 同一组件的 `.bookmark-card` 仅对 `border-color` 设置过渡。
  组件注释说明，移动悬停目标会使底部边缘的命中检测交替并导致玻璃效果或提示闪烁。
  后续样式调整应继续保持悬停命中区域稳定。
- [bookmark-hover-regression.mjs](../../scripts/bookmark-hover-regression.mjs) 使用真实构建产物、
  合成书签和全量请求拦截。现有断言覆盖边缘命中稳定性、空白圆角与上方卡片像素不变、
  键盘焦点、提示层级和链接点击；本文不声明该脚本在本次整理中已通过。

保留卡片自身的悬停反馈。仅凭这次历史录屏，不将相邻反光认定为已证实缺陷，
也不据此移除玻璃背景、阴影或描边。新的复现证据应按当前实现重新核对。
