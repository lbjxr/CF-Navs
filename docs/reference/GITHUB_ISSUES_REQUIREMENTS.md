## 2. 产品基线与规划原则

### 2.1 当前能力基线

以下是实现规划必须复用的现有能力，不是本轮新增需求：

- 分类最多两层，已有分类树选择器；分类表单可编辑父分类、标题、图标和私密属性。
- 首页已有登录态操作入口、书签编辑、分类分组、同级排序和跨分类整理会话。
- 跨分类整理通过统一草稿保存，后端接口为 `/api/bookmarks/reorganize`；状态冲突会返回冲突错误并要求刷新。
- 后台已有书签搜索、按页展示、跨页批量选择、批量删除和不落盘排序。
- 备份页已有按分类选择导出，选择二级分类时会补齐必要的一级父分类；导入支持追加合并和覆盖。
- 卡片尺寸设置当前 `card_size.width` 的有效范围为 44—400 px；详情卡片和极简卡片在网格中还有各自的布局最小值与响应式安全下限。
- 分类层级显示设置已通过 `category_display` 持久化，分别控制一级/二级标题字号和图标尺寸；首页、导航、搜索分组和预览消费统一派生值，移动端使用统一缩放。

相关源码参考：`src/views/Home.svelte`、`src/components/CategorySection.svelte`、`src/components/HomeCategoryScope.svelte`、`src/components/admin/BookmarkListPanel.svelte`、`src/components/BackupPanel.svelte`、`src/lib/sortableList.ts`、`worker/routes/bookmarks.ts`、`shared/types.ts`。

### 2.2 PC / 移动端共同原则

1. **登录边界一致：** #11 的首页新增分类入口仅在管理员登录态展示；匿名用户不看到管理操作，也不能通过前端入口绕过鉴权。
2. **数据规则一致：** PC 和移动端使用同一分类层级、书签归属、排序保存和权限规则，不为移动端建立另一套数据语义。
3. **可取消、可恢复：** 排序、批量移动和编辑都先形成可见草稿或待确认状态；保存失败时保留错误原因并恢复或重新拉取服务端数据。
4. **触控优先的替代操作：** 移动端不能把鼠标悬停、右键或精确拖拽作为唯一入口；无法稳定拖动时必须提供按钮、菜单或表单替代路径。
5. **窄屏不溢出：** 操作按钮允许只显示图标但必须保留可访问名称；弹层、下拉树、批量工具栏和错误提示不得超出视口。
6. **不以视觉默认值替代语义：** 分类路径、当前分类、高亮状态、选中数量和保存状态都必须有文本或可访问属性表达。

### 2.3 端侧规划断点

| 场景 | PC 规划 | 移动端规划 |
| --- | --- | --- |
| 首页分类操作 | 标题右侧或操作组内显示文字按钮；空间不足时允许收纳到操作菜单。 | 使用紧凑图标按钮或“更多操作”菜单，按钮保持触控尺寸和可访问名称。 |
| 分类选择 | 可展开树、键盘导航、路径清晰。 | 全宽或底部弹层树，支持滚动、展开、当前项高亮和明确关闭。 |
| 拖动排序 | 鼠标拖放、拖放目标高亮、空分类可接收。 | 优先提供“移动到分类”操作；若实现触控拖动，必须同时保留非拖动替代路径。 |
| 批量操作 | 表格勾选、跨页选择、顶部批量工具栏。 | 卡片/表格行勾选，底部或顶部吸附批量工具栏，目标分类选择使用弹层。 |
| 卡片尺寸 | 设置页实时预览多列、长标题和描述。 | 以单列/双列和最窄可用宽度验证，不允许设置值破坏点击区域或文字可读性。 |

## 4. 详细需求与 UI 规划

### R-01：一级分类到二级分类的书签移动与排序

**云端已明确的问题**：当前跨分类排序无法从主分类拖动到子分类；反馈认为“从主分类向子分类的移动”是跨分类拖动的主要使用场景。

**建议交互方案**

- PC 首页进入“排序”会话后，一级分类和其二级分类都属于同一个拖放组；一级分类网格、二级分类网格以及空分类都可作为目标。
- 拖动卡片经过目标分类时，目标区域显示明确的分类名和接收态；保存前只修改本地草稿，不立即写库。
- 保存时同时提交书签的新 `category_id` 和每个受影响分类的完整顺序；取消时恢复进入排序会话前的顺序。
- 服务端发现分类或书签集合已变化时返回冲突，前端提示“数据已变化，请刷新后重试”，不得以成功提示覆盖冲突。
- 移动端不把长按拖动作为唯一方案。首选在书签操作菜单中提供“移动到分类”，复用同一分类树和保存规则；若后续增加触控拖动，仍保留该入口。

**PC 验收标准**

- 可从一级分类拖入同一父级下的二级分类，也可拖入其他一级或二级分类；空目标分类可接收。
- 保存后书签分类归属、目标分类内顺序和后台列表分类路径均正确，刷新后不丢失。
- 拖动过程中不触发书签打开；取消不产生服务端写入。
- 过期数据保存失败时能看到错误，服务端数据重新加载后不保留错误草稿。

**移动端验收标准（建议补充）**

- 不依赖 hover、右键或不可发现的拖动手势即可完成跨分类移动。
- 分类树可滚动、可关闭，目标分类路径和当前选择清晰；保存成功或失败均有反馈。
- 若支持触控拖动，不能遮挡滚动和点击书签，也不能移除“移动到分类”替代入口。

**已确认决策**：移动端首版只提供书签操作菜单中的“移动到分类”，复用同一分类树和保存规则；普通浏览状态隐藏该菜单项，只有进入排序模式后才开放移动入口；不做触控拖动，但入口和数据契约必须为后续扩展“菜单 + 触控拖动”预留空间。验收反馈修复已完成 PC/移动端排序浮窗两行布局和移动菜单状态回归。

**实现证据**：`src/lib/homeSort.ts` 负责移动草稿与完整分类顺序；T2 定向单测 14/14，验收反馈定向交互/响应式测试通过；隔离 Chrome 390×844 已验证普通状态移动项隐藏、排序状态移动项显示，排序浮窗 left=12/right=363 且按钮第二行；T15/T16 进一步验证分类树鼠标/触摸滚动不穿透页面且不触发卡片拖拽；测试进程已清理。

### R-02：首页新建子分类入口

**云端已明确的需求**：登录状态下，在主分类的新建/排序操作附近增加新建子分类功能；原反馈标记为“感觉必要”。

**建议交互方案**

- 入口绑定当前一级分类，点击后直接打开已有分类编辑弹层的“新建”模式，并预填当前一级分类为 `parent_id`。
- PC 在一级分类标题操作组中显示“新建子分类”文字按钮；操作组拥挤时可收纳为带 aria-label 的菜单项。
- 移动端在一级分类标题的更多菜单中放置同名操作，菜单关闭后打开全宽或接近全宽的分类弹层。
- 成功后关闭弹层、刷新或局部更新分类树，并将新分类纳入当前一级分类的子分类范围；失败时保留表单内容和错误信息。
- 新建入口只对登录管理员展示；匿名首页和经常访问区域不显示管理按钮。

**验收标准**

- 从某一级分类进入新建子分类时，父分类已正确选中，不能误创建为一级分类。
- 取消不产生写入；成功后新分类标题、图标、父子关系和排序可在首页及后台看到。
- PC 和移动端入口均可发现、可键盘/触控操作，弹层不被底部或侧边导航遮挡。

**已确认决策**：入口预填当前一级分类为 `parent_id`，但允许用户在弹层中改选父分类；创建成功后自动滚动到新子分类并高亮，方便继续添加书签。

**T6 实现证据**：首页一级分类标题提供“新建子分类”入口；全局分类 modal 保持首页上下文，默认预填当前一级分类且可改选；移动端按钮加号图标可见；创建成功后刷新数据、回首页并选中新分类 tab。定向测试 12/12、type-check 0 errors/0 warnings、build 成功；独立 Chrome 已验证 PC 和 390×844 移动端入口/父级预填/成功选中。

### R-03：首页新增主分类入口

**云端已明确的需求**：在“经常访问”区域右侧增加新增主分类入口；原反馈标记为“感觉可选”，优先级低于 R-02。

**建议交互方案**

- PC 在“经常访问”标题右侧显示“新增主分类”；若该区域关闭或为空，将入口放在首页标题/主分类区域的登录态操作菜单中，避免入口随区域消失。
- 移动端使用经常访问标题栏的加号或更多菜单；区域为空时仍保留标题栏操作，不使用悬浮在卡片上的小按钮。
- 打开已有分类新建弹层，`parent_id` 默认为“无上级分类”；不复用 R-02 的当前父分类上下文。
- 成功后将新主分类加入首页分类树和导航；是否自动滚动到新分类需按确认结果实现。

**验收标准**

- 只有登录管理员看到入口；匿名用户的经常访问布局不因该入口产生空白占位。
- 创建结果是一级分类，父分类为空；不会因为从某个子分类上下文进入而意外创建为子分类。
- 关闭、保存失败和窄屏折叠均有明确状态，不发生重复提交。

**已确认决策**：R-03 延后，不与 R-02 同轮实现（原反馈标记为“可选”，优先级低于 R-02）。创建成功后同样自动滚动到新主分类并高亮。经常访问区域关闭、无数据、仅一列或移动端时的具体放置在实现 R-03 时再定。

**T7 实现证据**：管理员首页浮动操作提供“新增主分类”，作为经常访问区域不可用时的稳定入口；分类 modal 保持首页上下文并默认“无上级分类”；成功后回首页、新 root scope 高亮，匿名态不显示；定向测试 14/14、type-check 0 errors/0 warnings、build 成功，独立 Chrome 已覆盖 PC/390×844。

### R-04：首页编辑书签时定位当前分类

**云端已明确的需求**：在首页编辑书签，打开分类下拉列表后直接定位到书签当前分类，避免从列表顶部重新查找。

**建议交互方案**

- 打开编辑弹层时，将书签现有 `category_id` 传入分类树选择器；分类树根据完整路径展开父级并高亮当前项。
- “定位”只改变滚动、展开和高亮，不改变书签分类值；用户必须主动选择后才修改分类。
- PC 分类树支持键盘焦点移动，当前项进入可视区域；移动端弹层打开后自动滚动当前项到可视区域，并显示完整路径。
- 分类被删除或当前用户不可见时，显示“当前分类不可用”状态，不静默改到第一个分类；保存前按现有表单规则阻止无效引用。

**验收标准**

- 编辑有二级分类书签时，打开选择器会展开对应一级分类并定位到该二级分类。
- 编辑一级分类书签时，一级项高亮；打开和关闭选择器不会改变值。
- PC 键盘和移动端触控都能看到焦点/选中态；长分类列表不要求用户从顶部手动寻找。
- 保存仍使用现有分类引用校验，不能因“自动定位”绕过权限或层级限制。

**已确认决策**：定位 = 自动展开父级并滚动高亮当前项，不改变表单值；用户主动选择后才修改分类。新建分类后不在此流程自动选中。异常（分类被删除/不可见）显示“当前分类不可用”状态，不静默改到第一个分类。

**实现证据**：T3 在 `CategoryTreeSelect.svelte` 打开时等待树渲染并对 `aria-selected=true` 当前项执行 `scrollIntoView({ block: 'nearest' })`；当前二级书签的父级自动展开，trigger 显示完整路径；不可用值通过 `aria-describedby` 关联“当前分类不可用，请重新选择有效分类。”。定向单测 3/3、type-check 0 errors/0 warnings、独立 Chrome 回归通过。

### R-05：后台批量移动书签

**云端已明确的问题与方向**：新建分类或子分类后，逐个编辑书签修改分类很繁琐；希望在书签管理页查找、勾选多个书签并批量移动。

**建议交互方案**

- 复用现有搜索、分页和跨页选择：列表顶部显示“已选 N 项”，用户可选择当前页或继续跨页选择。
- 选中后显示“移动到分类”批量操作；目标选择器显示完整路径，例如“一级分类 / 二级分类”，并排除无效目标。
- PC 使用表格顶部批量工具栏和确认弹层；移动端使用吸附底部工具栏，目标分类使用全屏或底部弹层。
- 建议默认将书签追加到目标分类末尾，并按用户原有全局顺序处理；移动成功后清空选择、回到稳定页码并刷新分类路径。
- 建议服务端以一次受保护的批量操作完成归属更新和目标排序；集合校验失败时整体失败并返回冲突，不产生部分成功。
- 私密书签和私密分类继续遵循管理员权限；目标分类不存在、越权或跨层级非法时拒绝整批请求。

**PC / 移动端验收标准**

- 可在搜索结果和不同分页中保留选择，批量工具栏准确显示数量；取消选择不会改数据。
- 目标分类树显示完整路径、当前选项和禁用项原因；确认前能看到移动数量与目标。
- 成功后所有选中书签归属一致、顺序规则一致、列表路径更新；失败时不出现“部分成功”的误导提示。
- 移动端工具栏不遮挡列表操作，目标弹层可返回和关闭；PC 键盘可完成选择、打开目标和确认。

**已确认决策**：首版保留跨页选择；目标分类内提供“追加到末尾 / 插入到顶部”两个位置选项，默认追加到末尾（任意精确插入位置作为后续增强，不进首版）；集合校验失败时整体原子回滚，不产生部分成功；私密书签和私密分类继续遵循管理员权限，目标树中越权/非法目标禁用并说明原因。

**T4 实现证据**：新增 `POST /api/bookmarks/batch-move`，请求使用 `BookmarkBatchMoveReq` 的 `ids/category_id/position/expected`；服务端校验目标分类、选中集合和 `category_id/sort` 快照，并通过一次 D1 batch 更新归属与全局顺序。追加末尾、插入顶部成功，过期快照返回 `CONFLICT=1006` 且无写入；后台 UI 仍由 T5 实现。
**T5 实现证据**：后台列表保留跨页选择，selection toolbar 与列表滚动容器分离；PC 滚动列表不会覆盖工具栏，移动端工具栏固定在后台底部导航上方；确认弹层显示 11 项和目标路径，支持追加末尾/插入顶部；成功后清空选择并刷新，后端冲突时保留选择。独立 Chrome 390×844 已验证 toolbar 和弹层在视口内。

**前端交互最佳实践说明（建议实现规范）**

- **选择与反馈**：行首复选框 + 表头“全选当前页”；跨页选择时列表顶部常驻批量工具栏，明确显示“已选 N 项（跨 M 页）”，并提供“清空选择”。选择状态与分页、搜索解耦——翻页或改搜索条件不清空已选，除非用户主动清空。
- **批量操作入口**：有选中项时批量工具栏才出现（PC 吸附表格顶部，移动端吸附底部），避免空态占位。主操作按钮为“移动到分类”，次操作保留现有“批量删除”。
- **目标选择**：点击“移动到分类”打开分类树选择器（PC 弹层，移动端全屏/底部抽屉），显示完整路径“一级 / 二级”，禁用非法目标（不存在、越权、跨层级违规）并在禁用项旁说明原因。默认展开并高亮当前多数书签所在分类的父级，便于就近选择。
- **插入位置**：目标分类内提供“追加到末尾 / 插入到顶部”两个选项，默认“追加到末尾”（符合用户对“新增内容排在后面”的心理预期，且实现最简）；如需精确插入位置，作为后续增强，不阻塞首版。
- **确认与预防误操作**：确认弹层显示“将移动 N 个书签到 [目标路径]”，明确数量与目标后再提交；提交期间按钮进入 loading 并禁用重复点击。
- **结果与错误处理**：成功后清空选择、停留在稳定页码、刷新受影响分类路径，并给出“已移动 N 项”toast。失败时整体回滚，保留选择，展示服务端冲突原因（如“数据已变化，请刷新后重试”），不出现“部分成功”的误导提示。
- **接口冲突响应语义（已确认）**：复用 `/api/bookmarks/reorganize` 的冲突模式——请求集合与库中状态不一致（分类被删、书签集合过期）时返回 `ErrCode.CONFLICT`（1006），前端据此提示“数据已变化，请刷新后重试”并重新拉取；其它异常返回 `ErrCode.SERVER_ERROR`（1500）。批量移动接口沿用同一 `BookmarkReorganizeError` → `CONFLICT` 的判定，不把状态冲突笼统报成服务端错误。
- **可访问性**：复选框、批量工具栏按钮、分类树节点均有可访问名称；PC 支持键盘完成勾选、打开目标树、确认；移动端保持触控尺寸，工具栏不遮挡列表操作。

### R-06：分类和子分类字体、图标大小

**云端已明确的需求**：提供更改分类或者子分类字体和图标大小的功能。

**建议产品方案**

- 首版按层级提供全局设置：一级分类标题字体/图标大小、二级分类标题字体/图标大小；不立即引入每个分类独立覆盖，避免设置面板和数据模型膨胀。
- 设置作用于首页分类标题、首页二级分类标签、左侧/顶部导航和搜索分组；后台分类表格可保持紧凑固定尺寸，仅在预览中展示效果。
- 建议设置页使用两个层级分组，每组包含字号和图标尺寸数值控件，并提供实时预览；数值显示单位、最小/最大范围和移动端缩放说明。
- PC 预览展示长标题、无图标、图片图标和多子分类；移动端预览展示窄宽度、换行/省略、横向标签滚动和抽屉导航。
- 建议使用 CSS 变量或统一派生值传递到各显示场景，不在每个组件内复制一套硬编码比例。

**验收标准（待确认方案的基础）**

- 修改一级或二级设置后，所有列入作用域的显示场景同步更新，刷新后保持。
- 长标题、无图标、图片图标和两层分类在 PC、移动端均不发生不可读重叠、点击区域消失或横向页面溢出。
- 设置值越界、非数字和旧数据缺失时回退到安全默认值；保存失败不覆盖已保存设置。
- 一级和二级设置互不误写，且不会修改分类标题、图标内容或父子关系。

**已确认决策**：采用按层级全局设置——一级分类标题字体/图标尺寸一组、二级分类标题字体/图标尺寸一组；不引入每个分类独立覆盖，一级不继承二级。

**T8-R06 实现证据**：`CategoryDisplaySettingsSection.svelte` 已移动到“外观与卡片”的“高级设置”中，提供一级/二级字号与图标滑块；Home/Sidebar/CategorySection/Search/Preview 通过 CSS 变量消费，移动端统一 0.88 派生。验收反馈修复后，PC 大字号二级分类可通过滚轮/横向滚动条访问完整列表；独立 Chrome 验证设置卡片收起时不渲染、展开后位于 `.advanced-content` 内；定向测试和 type-check 通过。

**菜单位置（已确认）**：放入现有设置面板“外观与卡片”标签页的“高级设置”折叠区；该组控制分类标题/图标的视觉呈现，与卡片外观同属外观范畴，收起高级设置时不占用常规区域。

**建议默认值与区间（px，step=1，实时预览）**：参照现有分类标题 CSS（一级约 16px、二级约 15px）、`site_title_font_size` 16–72 滑块和 `card_icon_size` 40–100 归一化范围，给出更贴合分类场景的收敛区间：

| 设置项 | 默认值 | 建议区间 | 说明 |
| --- | --- | --- | --- |
| 一级分类标题字号 | 16 px | 12–28 px | 低于 12 px 移动端不可读，高于 28 px 挤压卡片区 |
| 一级分类图标尺寸 | 20 px | 14–36 px | 与一级标题字号协调，过大导致标题行换行 |
| 二级分类标题字号 | 14 px | 11–24 px | 二级层级视觉权重低于一级，上限收窄 |
| 二级分类图标尺寸 | 18 px | 12–32 px | 同二级标题，避免二级视觉压过一级 |

移动端：不单独暴露一套数值，改用统一缩放系数 0.88（取 0.85–0.9 区间中值，通过 CSS `clamp()` 或响应式变量派生），保证窄屏标题不换行溢出、图标不小于触控可辨识阈值。作用于首页分类标题、二级分类标签、顶部/侧边导航和搜索分组，统一用 CSS 变量派生，不在各组件硬编码比例。

### R-07：卡片最小宽度下限评估

**云端已明确的问题**：当前后台卡片最小宽度下限为 80，Issue 询问是否可以继续下调，或该限制是否有设计依据。

**当前实现基线**：设置表单、shared 归一化和 Worker 设置写入目前将 `card_size.width` 限制在 44—400 px；详情卡片网格与极简卡片网格还有各自的布局最小值，不能只修改一个数字后宣称所有卡片均可用。

**建议 UI / 产品方案**

- 在设置控件旁说明“卡片最小宽度”单位为 px、影响范围和过小值的风险；保留实时预览，不用没有依据的文案声称 80 是唯一正确值。
- 预览至少覆盖详情卡片、极简卡片、长标题、长描述、图片/文字图标、双列和多列布局；同时显示 PC 宽屏、窄屏和移动端结果。
- 以可用性测试结果决定下限：点击区域、图标识别、标题可读性、描述截断、网格列数和横向溢出全部通过后，才调整设置范围。
- 若详情风格和极简风格需要不同下限，应在 UI 中明确显示，而不是让一个通用下限产生不可解释的布局结果。
- 移动端允许使用响应式列宽覆盖桌面设置，但不能使卡片小于触控和内容可读性的安全阈值。

**验收标准**

- 控件、共享类型、归一化逻辑、预览和首页实际网格使用同一套已确认范围。
- 详情风格下任何允许保存的宽度都能在 PC 和移动端渲染完整卡片；低于 44 px 硬阈值的值在输入、保存和旧数据读取时一致钳制到 44 px，介于 44–80 px 之间的值允许保存但给出美观提示。
- 详情风格的标题/描述、极简风格的图标/标题、点击区域和响应式列数均有回归截图或行为记录。

**已确认决策**：

- **详情风格（`card_style === 'info'`）**：允许下调卡片最小宽度下限；硬安全阈值定为 44 px（取 40–48 px 量级中值，对齐移动端触控点击区域最小尺寸）。输入值 ≥ 44 px 且 < 80 px 时不拦截保存，但在控件旁显示“可能无法保证页面美观”提示，保留实时预览；低于 44 px 的输入在输入、保存和旧数据读取时一致钳制到 44 px。控件 `min` 设 44、`max` 保持 400。

- **极简风格（`card_style === 'icon'`）**：卡片最小宽度控件置灰不可修改。极简卡片尺寸已由“极简卡片图标大小”（`card_icon_size`，现范围 40–100 px）动态决定，卡片宽度随图标尺寸联动，无需也不应再单独设最小宽度；置灰时给出说明“极简风格下卡片大小由图标尺寸决定”。

**T8-R07 实现证据**：AdvancedSettingsSection 宽度控件 min=44/max=400，44–80 显示美观提示，icon 风格置灰并说明由图标尺寸决定；shared/client/Worker 保存和旧数据均归一化，API 非法值返回安全值。`CategorySection` 详情 Grid 轨道由归一化 `cardWidth` 驱动，桌面 width=44 轨道约 46px、width=80 约 83.5px、width=400 两列约 591px；390px 移动端 width=44 使用 150px 安全下限并双列，width=200/400 均单列 358px，均无横向溢出；定向测试 25/25、type-check 0/0、build 成功、console/page exception/failed request 均为 0。

### R-08：部分导出备份

**云端已明确的场景**：当用户维护两个或多个 CF-Navs 项目时，希望只导出某个分类及其书签，再同步到其他项目，而不是每次导出全部数据。

**当前能力对照**：仓库已有按分类选择导出、自动补齐二级分类所需一级父分类、书签过滤和设置处理；这属于“代码已存在、云端 Issue 仍 Open”的状态，不应再当作未实现功能重复规划。

- 导出结果应明确分类数、书签数和是否包含设置；不得覆盖目标项目未选择的内容。

- 在确认源码行为、部署版本和 Issue 原作者预期一致后，维护者可在云端补充说明并决定关闭或继续保留 #9 的该项内容。

**T9/T9b 核对证据**：既有导出单测 8/8；独立 Chrome PC 选择二级分类实际下载显示“已导出 2 个分类、1 个书签”，证明父分类补全；390×844 移动端分类树可滚动，导出 CTA 位于分类树下方、导入数据卡片上方的正常流式全宽布局，随内容滚动且不遮挡分类树最后一项。隔离 D1 `replace`/`merge` 回导和层级/归属/设置核对通过；导出数据组装与 replace/merge 逻辑未重写；部署版本和原作者预期仍待同步。

**已确认决策**：R-08 以现有“按分类选择导出”能力作为完成结果处理。核对当前部署版本与源码行为、确认与原作者预期一致后，在 #9 云端补充说明并标记该项完成，不重复实现已有能力。

7. **R-08 状态同步**：核对当前部署与导出行为后更新 #9 说明或关闭该项，不重复实现已有能力。
