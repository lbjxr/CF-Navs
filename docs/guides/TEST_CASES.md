## 2. 测试前准备

### 2.1 部署和安全准备

- [ ] 确认部署目标是 `develop` 对应的 Worker，不是 `main` 或其他环境。
- [ ] 确认 Cloudflare Worker 已绑定 D1 `DB` 和 KV `SESSION`。
- [ ] 首次安装环境已配置 `SETUP_TOKEN`；已安装环境不重复执行初始化。
- [ ] 使用测试管理员账号；不要在截图、日志或文档中记录密码和 Token。
- [ ] 如果已有正式数据，先通过备份功能保存完整备份。
- [ ] 导入 `replace`、批量删除、改密码用临时环境或可恢复测试数据。
- [ ] 浏览器打开 DevTools 的 Console 和 Network 面板。
- [ ] 测试期间记录：Console error、页面异常、失败请求和非预期 HTTP 4xx/5xx。

### 2.2 推荐测试数据

创建以下测试分类和书签。名称可按实际情况调整，但应保留层级和数量关系。

| 数据 | 建议内容 |
| --- | --- |
| 一级分类 A | `开发工具` |
| 一级分类 B | `资料` |
| 二级分类 A1 | `前端`，父级为 `开发工具` |
| 二级分类 A2 | `后端`，父级为 `开发工具` |
| 一级直属书签 | 至少 2 条，归属 `开发工具` |
| A1 书签 | 至少 3 条，归属 `前端` |
| A2 书签 | 至少 2 条，归属 `后端` |
| B 书签 | 至少 2 条，归属 `资料` |
| 长标题书签 | 标题和描述均较长 |
| 图标测试书签 | 分别使用 HTTP(S) 图标、文字/表情图标、Iconify 图标 |
| 私密数据 | 1 个私密分类或私密书签，仅用于公开模式测试 |

为了验证跨页选择，后台书签数量建议达到 11 条以上；为了验证空目标，保留一个没有书签的分类。

## 7. R-07 卡片宽度和卡片风格

### TC-R07-01 详情卡片宽度边界

**步骤：**

1. 进入“站点设置 → 外观与卡片 → 高级设置”。
2. 确认卡片最小宽度控件 `min=40`、`max=400`。
3. 依次输入并保存 `39`、`40`、`44`、`79`、`80`、`400`、`401`。
4. 每次保存后刷新首页。
5. 桌面和 `390×844` 移动端分别观察长标题、描述、图标和点击区域。
